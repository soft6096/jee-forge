# Tasks: 订单管理（US-001）

> 使用说明：这是第 ④ 步"任务拆解"的产物模板。根据技术方案 md 拆成可独立实现、可独立验证的任务清单。
> 格式：`[ID] [P?] [Phase] 描述（文件路径 + 验收方法）`
> - `[P]` = 可并行（不同文件、无依赖）
> - **完成标志（每个任务必填）**：一行**可独立判定**的验证——跑什么命令/curl/看什么日志关键字，能让"没有本任务上下文的人或全新 subagent"判断该任务做没做完。写法：`完成标志：<命令或关键字>`，如 `mvn compile 通过` / `curl POST /order 返回 200 + orderId` / `启动日志出现 Started xxx in x.x seconds`。禁止写成"实现 XX / 正常可用"这类判不了对错的描述
> - Phase 顺序固定：先数据层 → 再公共组件（0.5）→ 再业务 → 再接口/消费/调度
> - Phase 0.5 公共组件：技术方案"公共组件识别"章节有内容才拆；无重复逻辑 → 整个 Phase 留空，注明"无公共组件"
> - 按类型选一套模板，删掉不适用的
> - **无入口功能**（配置/工具，技术方案第零段判定）→ 跳过入口类 Phase（Controller/集成），只走 数据 → 公共组件 → 核心逻辑 → 验证
> 下方为**完整示例**（订单创建，Controller 类型），带占位符的骨架模板见各 Phase 注释。
>
> 📌 **样式要求**：速览框 / 对齐表格统一按 `通用-中间产物-MD样式规范.md`。

## Controller 类型模板（示例：订单创建）

### Phase 0 数据库（共享基础设施）

- [ ] T001 建表 SQL（按技术方案《数据模型与 SQL》章节 DDL，含索引/约束）
      - 来源：技术方案《数据模型与 SQL》章节（sys_order + order_item + order_status_log），**禁止独立 sql 目录**
      - 验收：在 MySQL 执行 DDL 成功，`SHOW CREATE TABLE sys_order` 与方案一致
  - [ ] T002 实体类 + Mapper 接口（简单查询走 BaseMapper/Wrapper，无 XML；复杂 SQL 场景才建 XML，见 database-standards 触发条件）
      - 文件：`src/main/java/com/example/order/domain/Order.java`、`OrderMapper.java`
      - 验收：`mvn compile` 通过

### Phase 0.5 公共组件（★ 技术方案"公共组件识别"有内容才拆）

- [ ] T003 XxxUtil
      - 文件：`src/main/java/com/example/common/util/XxxUtil.java`
      - 验收：后续功能任务必须调用它（禁止复制）
- [ ] T004 抽象基类 AbstractXxx（如适用，模板方法）
      - 文件：`src/main/java/com/example/common/base/AbstractXxx.java`
      - 验收：功能类必须继承它

### Phase 1 Service 层

- [ ] T005 创建订单核心逻辑（按技术方案"业务规则"小节：金额计算、库存扣减、状态流转）
      - 文件：`OrderServiceImpl.java`
      - 验收：金额计算正确（含折扣/运费）
- [ ] T006 纯转发方法（列表查询）
      - 验收：`mvn compile` 通过 + 被调用场景验证

### Phase 2 Controller 层

- [ ] T007 订单接口实现（入参→校验→Service→DB 走通）
      - 文件：`OrderController.java`
      - 验收：`POST /order` 集成验证通过（入参→校验→Service→DB 走通）

### Phase 3 验证

- [ ] T008 启动应用，curl 调通主流程
      - 验收：`curl -X POST /order -d '{}'` 返回 200 + 订单号

### Phase 4 收尾

- [ ] T009 注释、事务、权限注解（对照项目约束 #2/#4）
      - 验收：接口有 Javadoc，POST 有 @RequiresPermissions("order:order:add")，创建含 @Transactional

## 通用占位符骨架（复制用）

```
【功能名】任务拆解.md
├── Phase 0  数据库
│   ├── T001  建表 SQL（按技术方案《数据模型与 SQL》章节 DDL）→ 确认可执行
│   └── T002  实体类 + Mapper 接口（简单查询无 XML；复杂 SQL 才建）→ 编译通过
├── Phase 0.5  公共组件（★ 技术方案"公共组件识别"有内容才拆）
│   ├── T003  工具类/抽象基类
│   └── T004  （如适用）更多公共组件
├── Phase 1  Service 层
│   ├── T005  核心业务逻辑（按技术方案"业务规则"小节）
│   └── T006  纯转发方法
├── Phase 2  Controller 层
│   └── T007  接口实现 + 集成验证（文件路径）
├── Phase 3  验证
│   └── T008  启动应用调通主流程
└── Phase 4  收尾
    └── T009  注释、事务、权限注解核对
```

> 无公共组件时：删掉 Phase 0.5 块，任务编号顺延（T003 起），并注明"无公共组件"。
>
> 通用骨架/Listener/Job 的"验收"行即该任务的完成标志；按本模板生成实际任务拆解时，请把每行的 验收 落成**可独立判定**的完成标志写法（上方 Controller 类型各任务已示范）。

## 完成标准自检

- [ ] 每个任务有文件路径 + **可独立判定的完成标志**（一行命令/curl/日志关键字即可判定，无需上下文；判不了对错的描述不合格）
- [ ] 纯转发方法等无需单独验证的任务也写明完成标志（如编译通过 + 被调用场景验证）
- [ ] DDL（技术方案《数据模型与 SQL》章节）可执行、实体可编译
- [ ] 技术方案里的验收场景已作为逐任务完成标志/验证依据（无遗漏）
- [ ] 技术方案"公共组件识别"内容已翻译成 Phase 0.5 任务（无重复则 Phase 0.5 留空，注明"无公共组件"）
- [ ] 功能任务中公共组件复用点已写死（调用/继承，禁止复制粘贴）
- [ ] 依赖顺序正确（Phase 0/0.5 完成后才进 Phase 1）
- [ ] 文档开头有速览框 + Phase 概览表；表格分隔行带对齐标记
