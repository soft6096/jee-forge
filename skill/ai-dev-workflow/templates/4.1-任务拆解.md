# Tasks: 订单管理（US-001）

> 使用说明：这是第 ④ 步"任务拆解"的产物模板。根据技术方案 md 拆成可独立实现、独立测试的任务清单。
> 格式：`[ID] [P?] [Phase] 描述（文件路径 + 验收方法）`
> - `[P]` = 可并行（不同文件、无依赖）
> - Phase 顺序固定：先数据层 → 再公共组件（0.5）→ 再业务 → 再接口/消费/调度
> - Phase 0.5 公共组件：技术方案"公共组件识别"章节有内容才拆（先写契约测试先红 → 实现变绿）；无重复逻辑 → 整个 Phase 留空，注明"无公共组件"
> - 契约测试（Phase 1）必须先写并确认**红**——它是 AI 编码的标尺
> - 按类型选一套模板，删掉不适用的
> - **无入口功能**（配置/工具，技术方案第零段判定）→ 跳过入口类 Phase（契约测试/Controller/集成），只走 数据 → 公共组件 → 核心逻辑 → 验证
> 下方为**完整示例**（订单创建，Controller 类型），带占位符的骨架模板见各 Phase 注释。
>
> 📌 **样式要求**：速览框 / 对齐表格统一按 `通用-中间产物-MD样式规范.md`。

## 通用占位符骨架（复制用）

```
【功能名】任务拆解.md
├── Phase 0  数据库
│   ├── T001  建表 SQL（按技术方案《数据模型与 SQL》章节 DDL）→ 确认可执行
│   └── T002  实体类 + Mapper 接口（简单查询无 XML；复杂 SQL 才建）→ 编译通过

│   ├── T003  工具类/抽象基类 + 契约测试（先红 → 实现 → 绿）
│   └── T004  （如适用）更多公共组件 + 契约测试
├── Phase 1  契约测试（★ 最先写，先红）
│   └── T005  按验收场景写测试（文件路径）
├── Phase 2  Service 层
│   ├── T006  核心业务逻辑 + 单元测试（按技术方案"业务规则"小节）
│   └── T007  纯转发方法（跳过测试）
├── Phase 3  Controller 层
│   └── T008  接口实现 + 集成测试（文件路径）
├── Phase 4  验证
│   └── T009  quickstart：启动应用调通主流程
└── Phase 5  收尾
    └── T010  注释、事务、权限注解核对
```

> 无公共组件时：删掉 Phase 0.5 块，任务编号顺延（T003 起），并注明"无公共组件"。

## 完成标准自检

- [ ] 每个任务有文件路径 + 验收方法（AI 可独立执行）
- [ ] 契约测试先跑一遍，确认是**红的**
- [ ] DDL（技术方案《数据模型与 SQL》章节）可执行、实体可编译
- [ ] 技术方案里的验收场景全部翻译成测试用例（无遗漏）
- [ ] 技术方案"公共组件识别"内容已翻译成 Phase 0.5 任务（无重复则 Phase 0.5 留空，注明"无公共组件"）
- [ ] 功能任务中公共组件复用点已写死（调用/继承，禁止复制粘贴）
- [ ] 依赖顺序正确（Phase 0/0.5 完成后才进 Phase 2）
- [ ] 文档开头有速览框 + Phase 概览表；表格分隔行带对齐标记
