| 字段 | 必填 | 类型 | 说明 |

### 三、核心逻辑 → 调用骨架 + 业务规则

**调用骨架（必配，格式见 3.0 骨架"调用骨架必配"说明）**：

```text
# ============ Listener（MQ 消费者：反序列化 + 校验 + 转发）============
OrderPayListener
├─ onMessage(String body) → void                          # 订单支付回调 → OrderStatusService.syncStatus(body)

# ============ Service（业务编排 + 幂等/失败处理）============
OrderStatusServiceImpl
└─ syncStatus(String body) → void
    # 1. 反序列化 + 校验必填字段（orderId/status）；非法 → 丢弃 + 告警，不重试
    # 2. 幂等检查 → orderStatusLogMapper.selectByUniqueKey(orderId, status)；已存在 → 直接返回（ACK）
    # 3. 查订单当前状态 → orderMapper.selectById(orderId)；比较事件时间戳，旧消息忽略（乱序）
    # 4. 更新订单状态 → orderMapper.updateStatus(orderId, newStatus)
    # 5. 写状态日志 → orderStatusLogMapper.insert(log)；手动 ACK

# ============ Mapper（数据访问，函数下附对应 SQL，SQL 必带用途注释）============
OrderMapper
├─ selectById(Long id) → Order                            # 幂等前置：查订单（BaseMapper 内置）
└─ updateStatus(Long orderId, String status) → int        # 状态更新
    └─ SQL:
        -- 用途：更新订单状态（支付回调）；归属：OrderMapper.updateStatus；条件：id + 未删除
        UPDATE sys_order SET status = #{status}, update_time = NOW()
        WHERE id = #{orderId} AND deleted = 0

OrderStatusLogMapper
├─ selectByUniqueKey(Long orderId, String status) → OrderStatusLog   # 幂等检查
│   └─ SQL:
│       -- 用途：幂等检查（按订单+状态查是否已处理）；归属：OrderStatusLogMapper.selectByUniqueKey
│       SELECT * FROM order_status_log WHERE order_id = #{orderId} AND status = #{status}
└─ insert(OrderStatusLog log) → int                       # 写状态日志（BaseMapper 内置，唯一键兜底幂等）
```

**业务规则（复杂业务必写，同 3.1 要求）**：状态流转 / 计算规则 / 并发处理

- **跨功能项规则**（如状态机横跨多入口）→ 按 3.0 归属规则：引用最先触碰的功能项编号，只写本入口触发的迁移

### 四、关注点 → 幂等与失败处理

| 关注点 | 要求 |
| :--- | :--- |
| 幂等 | 唯一键 order_id + status（order_status_log 建联合唯一索引），重复消息直接跳过；捕获 DuplicateKeyException 视为成功 |
| 失败重试 | 消费异常重试 3 次（指数退避 1s/2s/4s），仍失败进死信队列（order.status.dead.queue）+ 告警 |
| 反序列化失败 | 不重试，直接丢弃 + 告警日志 |
| 订单不存在 | 不处理，ACK + 告警（避免死信堆积） |

> [!WARNING] 幂等是生死线
> 重复消息必须幂等（唯一键或状态位）；消费失败必须重试 + 死信，禁止直接吞异常不处理。
