## 四段式内容（并入 3.0 骨架，本类型必填）

### 一、入口定义 → 调度配置

| 配置项 | 值 |
| :--- | :--- |
| Job 类 | OrderTimeoutJob |
| cron 表达式 | `0 */5 * * * ?`（每 5 分钟执行一次） |
| 触发器说明 | 关闭超过 30 分钟未支付的订单 |

### 二、数据契约 → 无入参（跳过）

- 定时触发无请求体；涉及数据通过查询 SQL 筛选（见第三段）

### 三、核心逻辑 → 调用骨架 + 业务规则

**调用骨架（必配，格式见 3.0 骨架"调用骨架必配"说明）**：

```text
# ============ Job（定时触发：防重入 + 调度执行）============
OrderTimeoutJob
└─ execute() → void                                       # 订单超时关闭 → OrderService.closeTimeoutOrders()

# ============ Service（业务编排 + 防重入/批处理）============
OrderServiceImpl
└─ closeTimeoutOrders() → int
    # 1. 防重入：获取分布式锁 → redisLockUtil.tryLock("order.timeout.lock", 600)；失败直接返回 0
    # 2. 查询超时订单 → orderMapper.selectTimeoutOrders(30, 500)（LIMIT 500 防长事务）
    # 3. 逐条处理（每条独立事务）：关闭订单 → orderMapper.closeOrder(orderId)；
    #    释放库存 → stockService.releaseStock(orderId)；失败条记日志不中断，保持 PENDING
    # 4. 写执行日志 → jobLogMapper.insert(count, costMs)
    # 5. 释放锁 → redisLockUtil.unlock("order.timeout.lock")

# ============ Mapper（数据访问，函数下附对应 SQL，SQL 必带用途注释）============
OrderMapper
├─ selectTimeoutOrders(int minutes, int limit) → List<Order>   # 筛选超时订单
│   └─ SQL:
│       -- 用途：筛选超时未支付订单（Job 执行）；归属：OrderMapper.selectTimeoutOrders
│       -- 条件：状态 PENDING + 超过 minutes 分钟 + 未删除；LIMIT 防长事务
      │       SELECT order_id FROM sys_order
      │       WHERE status = 'PENDING'
      │         AND create_time < DATE_SUB(NOW(), INTERVAL #{minutes} MINUTE)
      │         AND deleted = 0
│       ORDER BY create_time ASC
│       LIMIT #{limit}
└─ closeOrder(Long orderId) → int                        # 逐条关闭订单
    └─ SQL:
        -- 用途：关闭超时订单（逐条处理）；归属：OrderMapper.closeOrder；条件：id + 仍为 PENDING
        UPDATE sys_order SET status = 'CLOSED', update_time = NOW()
        WHERE id = #{orderId} AND status = 'PENDING'

JobLogMapper
└─ insert(JobExecutionLog log) → int                     # 写执行日志（BaseMapper 内置）

# ============ 公共组件 ============
RedisLockUtil.tryLock(key, timeoutSec) / unlock(key)     # 防重入分布式锁
```

**业务规则（复杂业务必写，同 3.1 要求）**：状态流转 / 计算规则 / 并发处理

- **跨功能项规则**（如状态机横跨多入口）→ 按 3.0 归属规则：引用最先触碰的功能项编号，只写本入口触发的迁移

### 四、关注点 → 防重入 / 批处理 / 异常告警

| 关注点 | 要求 |
| :--- | :--- |
| 防重入 | Redis 分布式锁，key=order.timeout.lock，超时 600s（> 单轮执行时间） |
| 批处理 | 每次最多 500 条，避免长事务；剩余等下次调度 |
| 单条失败隔离 | 逐条 try-catch，失败记日志，不影响批量 |
| 告警 | 批量失败率 > 20% → 发送告警（钉钉/邮件，走 AlertService） |

> [!WARNING] 防重入是生死线
> 分布式锁超时必须大于单轮执行时间；批处理必须 LIMIT 限流防长事务；单条失败必须隔离，禁止一条失败拖垮整批。
