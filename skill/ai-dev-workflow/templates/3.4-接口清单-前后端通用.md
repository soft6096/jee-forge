# 接口清单（前后端通用）- <功能名>

> 使用说明：这是第 ③ 步技术方案生成的**功能项级接口清单**（独立产物，不并入技术方案 md）。
> **生成时机**：该功能项（Controller 类型）技术方案生成后同步生成——把方案「一、入口定义 → 接口明细」中的 URL / 入参 / 出参**汇总为本清单**。
> **产物命名**：`3.<功能项序号>.2-<功能名>-接口清单（前后端通用）.md`（如 `3.1.2-订单创建-接口清单（前后端通用）.md`；技术方案为 `3.<功能项序号>.1-<功能名>-技术方案.md`）。
> **用途**：后端开发结束后**直接把本清单给前端**——前端据此联调 / Mock / 核对，零沟通；模块联调时，各功能项接口清单合起来即全模块接口全集。
> **数据来源**：本功能项技术方案（3.1 接口明细）——**内容必须与方案一致，禁止另起一套说法**；方案改 → 本清单同步改。
> **纯后端模块**：功能项无 HTTP 接口（Listener/Job/无入口）→ 不生成本清单，在对应技术方案注明"无 HTTP 接口，跳过接口清单"。
>
> 📌 **样式要求**：速览框 / 对齐表格 / callout 统一按 `00-中间产物-MD样式规范.md`。

## 二、接口明细（每个 URL 独立小节：URL + 方法 + 入参 JSON + 出参 JSON 成功/失败）

### #1 POST /api/v1/users — 创建用户

**入参 JSON**：

```json
{
  "username": "zhangsan",
  "nickname": "张三",
  "email": "zhangsan@example.com",
  "phone": "13800138000",
  "password": "abc123456",
  "deptId": 101,
  "roleIdList": [1, 2],
  "status": "0"
}
```

**出参 JSON（成功 / 失败）**：

```json
// 成功
{ "code": 200, "message": "操作成功", "data": { "userId": 10001, "username": "zhangsan" } }
// 失败（用户名已存在，409）
{ "code": 409, "message": "用户名已存在", "data": null }
// 失败（参数校验错误，400）
{ "code": 400, "message": "email 格式不正确", "data": null }
```

### #2 GET /api/v1/users/{userId} — 用户详情

**入参**：路径参数 `userId`（Long，必填），无请求体

**出参 JSON（成功 / 失败）**：

```json
// 成功
{ "code": 200, "message": "操作成功", "data": { "userId": 10001, "username": "zhangsan", "email": "zhangsan@example.com", "status": "0" } }
// 失败（用户不存在，404）
{ "code": 404, "message": "用户不存在", "data": null }
```

### #3 GET /api/v1/users/list — 分页查询用户

**入参**：QueryString `pageNum=1&pageSize=10&username=zhang&status=0`

**出参 JSON（成功 / 失败）**：

```json
// 成功（分页）
{ "code": 200, "message": "操作成功", "data": { "total": 1, "rows": [ { "userId": 10001, "username": "zhangsan", "status": "0" } ] } }
// 失败（分页参数非法，400）
{ "code": 400, "message": "pageSize 不能大于 100", "data": null }
```
