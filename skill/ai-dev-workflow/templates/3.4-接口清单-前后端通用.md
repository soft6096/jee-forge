# 接口清单（前后端通用）- <功能名>

> 使用说明：这是第 ③ 步技术方案生成的**功能项级接口清单**（独立产物，不并入技术方案 md）。
> **生成时机**：该功能项（Controller 类型）技术方案生成后同步生成——把方案「一、入口定义 → 接口明细」中的 URL / 入参 / 出参**汇总为本清单**。
> **产物命名**：`3.<功能项序号>.2-<功能名>-接口清单（前后端通用）.md`（如 `3.1.2-订单创建-接口清单（前后端通用）.md`；技术方案为 `3.<功能项序号>.1-<功能名>-技术方案.md`）。
> **用途**：后端开发结束后**直接把本清单给前端**——前端据此联调 / Mock / 核对，零沟通；模块联调时，各功能项接口清单合起来即全模块接口全集。
> **数据来源**：本功能项技术方案（3.1 接口明细）——**内容必须与方案一致，禁止另起一套说法**；方案改 → 本清单同步改。
> **纯后端模块**：功能项无 HTTP 接口（Listener/Job/无入口）→ 不生成本清单，在对应技术方案注明"无 HTTP 接口，跳过接口清单"。
>
> 📌 **样式要求**：速览框 / 对齐表格 / callout 统一按 `通用-中间产物-MD样式规范.md`。
> 📌 **第一硬要求**：**本文档里每个 JSON 的每一个字段，都必须在行尾带 `//` 注释**（含嵌套对象、数组元素，含失败示例的 `code`/`message` 等外层字段）——这是本清单给前端"零沟通"的前提，详见 §二 的「三条硬要求」与文末自检命令。

## 调用前置（本模块通用，一模块内各接口清单保持一致）

> 每个接口都"长在"同一套调用约定上（基地址 / 鉴权 / 统一返回体 / 失败语义）。**先在这里讲一次**，接口明细里不再重复，前端可直接照着发请求。

| 项目 | 内容 |
| :--- | :--- |
| **请求方式** | POST + JSON（`Content-Type: application/json`）；写操作一律 POST，查询也用 POST（按项目硬规则填，勿凭 REST 直觉写 PUT/PATCH/DELETE） |
| **请求地址** | 本地直连 `http://<host>:<port>`（服务无 context-path）；经网关访问走 `http://<gateway-host>:<gateway-port>` |
| **鉴权** | 请求头 `Authorization: <token>`；服务端据此取登录信息 —— token 缺失/失效返回 **401**（全局文案固定「<按项目填，如：没有授权>」），权限不足返回 **403** |
| **响应结构** | 统一返回体 `Result<T>`：`code` / `message` / `data` / `timestamp` / `traceId`；**`data` 为 null 时不返回该字段**（NON_NULL 序列化策略）；`traceId` 同时写入响应头 |
| **HTTP 状态码** | **业务异常、权限异常、参数校验异常一律以 HTTP 200 返回**（全局异常处理器统一 `@ResponseStatus(OK)`），失败语义只体现在 `code` —— 前端**不要按 HTTP 状态码分支**；若项目不是这个口径，改为项目实际口径并在本行写明 |
| **错误码口径** | **业务异常 = 500 / 权限类 = 403 / 鉴权 = 401**，**不使用 400**（按项目约定填；前端按 `message` 文案分支，不按 `code` 细分） |
| **幂等 / 防重** | 有防重提交或幂等键的在这里写明（如 `@PreventDuplicateSubmit`），无则删掉本行 |

## 二、接口明细（每个 URL 独立小节：URL + 方法 + 入参 JSON + 出参 JSON 成功/失败）

> [!WARNING] 三条硬要求（缺一不可）
>
> 1. **JSON 必给**：每个接口必须有**入参 JSON 示例** + **出参 JSON 示例（成功 / 失败）**——禁止只给字段表不给 JSON；入参可为空时也要写 `{}` 并注明"无入参"。
> 2. **每个字段逐字段注释**：JSON 里**每一个字段行尾都要有 `//` 注释**（含嵌套对象字段、数组元素字段、以及失败示例里的 `code`/`message`/`timestamp`/`traceId`）。注释至少包含：**含义 + 类型 + 必填性**；字典字段补**字典码**，日期字段补**格式**，枚举字段补**取值**。缺注释 = 前端看不懂 = 清单不合格。
> 3. **失败示例与错误码一一对应**：每个失败示例单独成对象且逐字段注释；`message` 必须用**后端异常枚举原文**（禁止用日志文案、禁止自造文案）；多个字段会同时校验失败时，说明拼接规则（如"按英文句点 `.` 拼接"）。

### #1 POST /api/v1/users — 创建用户

**入参 JSON**（8 字段）：

```json
{
  "username": "zhangsan", // 【必填】String，用户名（≤32；全局唯一，重复 → 500「用户名已存在」）
  "nickname": "张三", // 【选填】String，昵称（≤32）
  "email": "zhangsan@example.com", // 【选填】String，邮箱（格式校验；格式错 → 500「email 格式不正确」）
  "phone": "13800138000", // 【选填】String，手机号（11 位）
  "password": "abc123456", // 【必填】String，初始密码（≥8 位）
  "deptId": 101, // 【选填】Long，部门ID（不传=不归属部门）
  "roleIdList": [1, 2], // 【选填】Array<Long>，角色ID列表；元素含义：1=管理员、2=普通用户
  "status": "0" // 【选填】String，状态（字典 <字典类型码>）：0-正常 / 1-停用；不传默认 0
}
```

**出参 JSON（成功 / 失败）**：

```json
// 成功（200）
{
  "code": 200, // 【状态码】Integer，200=成功；失败时取 401 未登录 / 403 无权限 / 500 业务或参数校验异常
  "message": "操作成功", // 【提示信息】String，成功固定为「操作成功」
  "data": 10001, // 【业务数据】Long，新用户ID（供前端跳详情）
  "timestamp": "2026-09-29 20:05:10", // 【时间戳】String，响应生成时间
  "traceId": "c3d4e5f6a7b8" // 【链路ID】String，全局响应增强注入，同时写入响应头
}
// 失败（500 用户名已存在）
{
  "code": 500, // 500=<后端异常枚举名，如 USER_NAME_EXISTS>
  "message": "用户名已存在", // 【提示信息】String，后端异常枚举原文（前端按文案分支）
  "timestamp": "2026-09-29 20:05:10", // 【时间戳】String，响应生成时间
  "traceId": "c3d4e5f6a7b8" // 【链路ID】String
}
// 失败（500 参数校验不通过：必填缺失）
{
  "code": 500, // 500=参数校验未通过（多个字段同错时按英文句点拼接返回）
  "message": "用户名不能为空", // 【提示信息】String，DTO 校验注解 message 原文
  "timestamp": "2026-09-29 20:05:10", // 【时间戳】String
  "traceId": "c3d4e5f6a7b8" // 【链路ID】String
}
// 失败（403 非管理员）
{
  "code": 403, // 403=<后端异常枚举名，如 NO_OPERATE_PERMISSION>
  "message": "无权执行该操作", // 【提示信息】String，后端异常枚举原文
  "timestamp": "2026-09-29 20:05:10", // 【时间戳】String
  "traceId": "c3d4e5f6a7b8" // 【链路ID】String
}
// 失败（401 未登录 / token 失效）
{
  "code": 401, // 401=鉴权未通过（全局文案固定）—— 注意：本行 HTTP 状态码仍是 200
  "message": "没有授权", // 【提示信息】String，全局鉴权失败文案
  "timestamp": "2026-09-29 20:05:10", // 【时间戳】String
  "traceId": "c3d4e5f6a7b8" // 【链路ID】String
}
```

## 三、字段口径（本功能项跨接口共享字段/枚举/字典，避免各接口各说一套）

| 字段 / 枚举 | 取值 | 口径说明 |
| :--- | :--- | :--- |
| `status` | `"0"` 正常 / `"1"` 停用 | 用户状态（字典 **<类型码>**）：**全局一致**，接口同时返回 `statusName` 中文名，前端直接展示勿自行映射 |
| `version` | Integer | 乐观锁版本号：**必须原样回传**；保存成功后 `+1`，前端需重新拉详情再编辑 |
| `currentPage` / `pageSize` | `Long` | 继承基类，默认 1 / 10；上限 **100**，超限静默截断 |
| `Result.code` | 200 / 401 / 403 / 500 | **业务异常统一 500，权限类 403，鉴权 401**（不使用 400）；前端按 `message` 分支 |
| `Result.data` | 各接口不同 | `data` 为 null 时**该字段整体不返回**（NON_NULL）——前端取数前先判存在，勿依赖 `data: null` |
| 日期字段 | `yyyy-MM-dd HH:mm:ss` | 时区（如 GMT+8）；**统一 `java.util.Date`，禁 `java.time.*`**（按项目约定填） |
| 多值字段 | 数组 | DB/Entity 为逗号分隔 String、DTO 用 `List`、Service 层互转（按项目约定填） |
| `*Name` 后缀字段 | 中文名 | 后端已转义，前端**直接展示，勿再查字典** |
| … | … | … |

> **口径表只登记"跨接口共享"的字段/枚举**；只属于单个接口的字段写在对应接口的 JSON 注释里，不在此重复。

## 生成后自检（先跑机械核对，再逐条打勾）

**① 逐字段注释机械核对**——在产物所在目录执行，输出**必须为 0**（统计每个 `json` 代码块内"以引号开头且行尾无 `//`"的字段行）：

```bash
awk '/^```json/{inb=1;next} /^```/{inb=0} inb && /^[[:space:]]*"/ && !/\/\//{c++} END{print c+0}' "3.<功能项序号>.2-<功能名>-接口清单（前后端通用）.md"
```

输出不为 0 → 按行号补齐注释后重跑；**不要靠肉眼抽查**（长出参极易漏注释）。

**② 失败文案与代码一致性核对**（有后端代码后回查）：逐个失败示例的 `message`，在异常枚举类（如 `XxxExceptionEnum`）里逐个搜到**原文**；搜不到 → 说明写的是日志文案或自造文案，必须改。
