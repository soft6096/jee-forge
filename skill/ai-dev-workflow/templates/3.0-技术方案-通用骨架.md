# 技术方案：通用骨架（所有类型共用）

> 使用说明：这是第 ③ 步"技术方案"的产物模板（通用骨架，所有类型共用一份）。
> **生成一份完整技术方案 = 本骨架（基本信息 + 通用章节）+ 命中类型的 3.x 模板（四段式内容）+ 示例。**
> 3.x 类型模板是"类型导航表"里某一行的展开实例，只含类型特有内容，不含通用章节。
> 无入口形态的功能：只写本骨架，跳过类型段（见"第零段 功能定性"）。
>
> 📌 **样式要求**：生成前先读 `templates/通用-中间产物-MD样式规范.md`——速览框 / 对齐表格 / mermaid 配色 / callout 统一按该规范。

## 使用流程

1. 从功能清单读功能项的**类型列**（Controller / Listener / Job / 无入口）
2. **第零段 功能定性**：无入口形态 → 只写通用章节，结束
3. 有入口形态 → 按【类型导航表】取对应 3.x 模板，把其四段内容并入本骨架
4. 复合形态（如 HTTP 接口 + MQ 触发补偿）→ 主类型四段为主，次类型对应段以小标题追加
5. 对照 3.x 模板的"类型特有自检" + 本骨架"完成标准自检"逐条核对

## 第零段 功能定性（先判，再决定走不走类型段）

### 数据模型与 SQL（★ 模块全量 SQL 单一事实源，SQL 全量注释）

> [!IMPORTANT] 存放口径
> **模块所有 SQL 一律写在本章节，禁止独立 `sql/` 目录、禁止"完整 DDL 落盘 schema.sql"式外推**（历史做法 `docs/sql/xxx.sql` 已废弃）。
> 本章节是 4.1 建表任务与 5.3 验收建库的唯一 SQL 来源；编码 Agent 的 schema/初始化脚本从这里派生。
> 共享表（被多个功能项使用）的 DDL 定义在**最先触碰它的功能项**方案，其他功能项只引用 #N，不重复贴。
> 与三、核心逻辑调用骨架中的 Mapper 内联 SQL **一一对应**，两处不得出现两套说法。
> **示例 SQL 的表名/字段名仅示意**：实际表名前缀按 2.1 项目约束定义（database-standards：统一业务前缀，如 `t_`；RuoYi 系项目常用 `sys_` 系统表前缀），逻辑删除字段按约束（通用规范 `deleted` / 存量项目老约定 `del_flag`），禁止与项目现有表风格混用。

> [!WARNING] SQL 全量注释（强制）
> **本章节所有 SQL 语句必须带注释，一条不漏**（DDL / DML / 查询 SQL 全覆盖）：
> - **建表 DDL**：每个字段 `COMMENT '...'`（含义/枚举取值/单位/时区约定）+ 表级 `COMMENT='...'`（见 database-standards `standards/table-design-standards.md`）
> - **初始化 / 数据变更 DML**：语句上方 `--` 注释标注用途（初始化哪张表/订正什么数据/幂等依据）
> - **业务查询 SQL**：语句上方 `--` 注释标注用途 + 归属 Mapper 函数（如 `OrderMapper.selectTimeoutOrders`）+ 关键参数/条件说明
> - SQL 注释与代码注释同源（见 4-AI 注释规范）：注释写业务含义，禁止无注释裸 SQL

**1. 建表 DDL（完整 CREATE TABLE，表 + 关联表 + 索引 + 约束 + 全字段 COMMENT）**：

```sql
-- 本功能项引入的表（共享表引用最先触碰的功能项方案 #N）；完整语句，禁止只给字段摘要
CREATE TABLE sys_order (
  id          BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID',
  order_no    VARCHAR(32) NOT NULL COMMENT '订单号（业务唯一）',
  status      VARCHAR(20) NOT NULL DEFAULT 'PENDING' COMMENT '状态：PENDING-待支付 PAID-已支付 CLOSED-已关闭',
  amount      DECIMAL(10,2) NOT NULL DEFAULT 0 COMMENT '订单金额（元）',
  deleted     TINYINT NOT NULL DEFAULT 0 COMMENT '逻辑删除：0-未删 1-已删',
  create_time DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间（Asia/Shanghai）',
  UNIQUE KEY uk_order_no (order_no),
  KEY idx_status_create (status, create_time)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='订单表';
```

**2. 初始化 / 数据变更 SQL（DML，每条必带用途注释）**：

```sql
-- 初始化订单状态字典（幂等：存在同 dict_type 则跳过）
INSERT INTO sys_dict_type (dict_name, dict_type, status) VALUES ('订单状态', 'order_status', '0');
```

**3. 业务查询 SQL（本模块 Mapper 全量，与三、核心逻辑调用骨架内联 SQL 一一对应，每条必带注释）**：

```sql
-- 用途：筛选超时未支付订单（Job 超时关闭用）；归属：OrderMapper.selectTimeoutOrders
-- 参数：minutes=30（超时分钟）、limit=500（批处理上限防长事务）；条件：状态 PENDING + 超时 + 未删除
SELECT order_id FROM sys_order
WHERE status = 'PENDING'
  AND create_time < DATE_SUB(NOW(), INTERVAL 30 MINUTE)
  AND deleted = 0
ORDER BY create_time ASC
LIMIT 500;
```

> [!NOTE] 简单 CRUD 不入本章节
> BaseMapper 内置方法（selectById/insert 等）无需贴 SQL；只登记**自定义 SQL**（含动态条件/JOIN/批量/UPDATE 定制）。

## 四段式结构（3.x 模板的统一语法）

每份类型模板按四段组织，本骨架定义其含义：

| 段 | 内容 | 备注 |
| :---: | :--- | :--- |
| 一、入口定义 | 功能怎么被触发：接口清单 / 监听配置 / 调度配置 | 所有类型必有 |
| 二、数据契约 | 入参出参形态：JSON / 消息体 / 无 | Job 无入参，可跳过 |
| 三、核心逻辑 | **调用骨架**（分层调用 + 中文编号步骤 + Mapper 内联 SQL）+ 业务规则（状态流转/计算规则/并发处理） | 简单转发可注明"纯转发"；复杂业务必写业务规则 |
| 四、关注点 | 横切：权限 / 事务 / 幂等 / 防重入 / 批处理 / 告警 | 按类型必选 |

> [!WARNING] 调用骨架必配
> 核心逻辑段**必配"调用骨架"**：用 text 代码块按层（Controller/Listener/Job → Service → Mapper）展示类与函数，函数体用**中文编号步骤**描述；**调用关系用 `→` 标注**（Controller → Service → Mapper）；Mapper 函数下**内联对应 SQL**（与"数据模型与 SQL"章节一一对应）。简单函数一行注释说明用途即可，不写实现代码。mermaid 时序图/流程图仅作复杂交互的可选增强，不强制。
