# Java 后端追问模式库（1.3 澄清用）

> 用途：`/clarify`（1.3）打开时**先扫描本库**，把 AI 会"合理地替产品/需求做主"的字段/枚举/状态/权限歧义机械地识别出来、变成尖锐追问交人确认——而不是自己拍板（拍板 = 后续方案/编码跑偏的源头）。
> 与 1.2 的关系：req-gate 已裁决或已标 🔲 的项，1.3 直接承接裁决，**不重复追问**。
> 定位：**经验型资产，会增长**。种子条目自 SDD 整车 PRD 模式库移植并翻译为 Java 后端语境；以后真实踩到本库没问到的坑，按文末"增长回路"追加为 P{n}。

## 怎么用（1.3 澄清时的扫描动作）

1. 打开 `/clarify` 后，先加载本库，逐条对照**机械触发信号**扫描功能清单（每个字段/状态/动作/权限表述）。
2. **命中信号就必须问，不许自己选答案**——即使功能清单某处像是暗示了答案，只要没定义/有矛盾，就是待澄清。
3. 追问要**具体到字段/状态/动作，给出候选答案让人二选一**，禁止泛问"这里什么意思"。
4. 生成的每个问题进入 `1.3-澄清问题清单.md`（含功能项 + AI 建议默认值），由人逐项确认。
5. **去重规则（强制）**：
   - 同一字段被多条模式命中 → 只出**优先级最高**的一条（P1 > P8 > P6 > P3 > P9 > P10）；
   - req-gate（1.2）已裁决 / 已标 🔲 的项 → 直接承接，不重复问。

## 种子模式（6 条）

### P1 计算 vs 录入（派生 vs 输入）⭐ 命中率高
- **机械信号**：数量/金额/统计类字段，同时标"录入/计算/只读=是"，或同一度量字段在主表与明细表都出现，或方案含"汇总/统计"但需求没说来源。
- **为什么致命**：决定该字段是**存储列还是计算结果**——两套数据模型、两套 DDL。
- **追问模板**：「`<字段>` 是用户新增时**录入**的值，还是系统按 `<维度>` **统计/汇总/计算**出来的？若是计算，计算规则是什么？若录入，它只是**约束校验**还是**原样存储**？」

### P3 枚举未穷举 / 未给编码 ⭐ 命中率高
- **机械信号**：字段标"下拉/枚举/类型"但没列全取值，或列了文案没给编码，或后续流程/页面引用了枚举外取值。
- **为什么致命**：枚举不齐 → 建表/字典/代码全链返工；AI 若擅自补取值 = 编造业务。
- **追问模板**：「`<字段>` 的**完整字典值**有哪些？各值对应**编码**是什么？（是否已有存量枚举可复用——见 1.2 术语对齐结论；禁止擅自新增）」

### P6 字段身份 + 生命周期 ⭐ 条件命中（出现同名/近义字段时）
- **机械信号**：多处出现同名/近义字段（如"新增附件 vs 验收附件"）；附件/文件/快照类字段无实体定义；没说清该字段**在哪个状态可写/可改**。
- **为什么致命**：同名不同义 → Entity 字段归属错、改一个漏一个。
- **追问模板**：「`<A处>` 和 `<B处>` 的 `<字段>` 是**同一份数据**吗？各自在**哪个状态/阶段**可写、可改、只读？存储的是**值快照**还是**引用 ID**？」

### P8 聚合方向（主表 vs 明细表一致性）⭐ 条件命中（主从表场景）
- **机械信号**：主表有汇总度量、明细表有同名度量，需求写"需一致"但没说**谁算谁**、不一致时以谁为准。
- **为什么致命**：决定保存时是**校验一致**还是**实时计算**——事务边界和一致性策略两套写法。
- **追问模板**：「`<主表字段>` 是 `<明细>` **汇总**来的吗？保存时**校验一致**还是**由明细实时汇总展示**？若校验，不一致时**拒绝还是覆盖**？以谁为准？」

### P9 状态集自洽（状态机不闭合）⭐ 命中率高（Listener/Job 场景）
- **机械信号**：状态枚举里的某状态无迁移边（没有按钮/动作能到它、从它出）；按钮/流程用到的状态不在枚举里；需求写了"超时/驳回/取消"等分支但没走到终态。
- **为什么致命**：状态机不闭合 → Listener/Job 的状态流转代码在编码期才发现缺分支，验收场景必漏。
- **追问模板**：「`<状态A>` 在枚举里但没有流转路径（谁进入它？从它到哪？）；`<状态B>` 在 `<>` 逻辑里用到但不在状态枚举——请对齐**完整状态集与迁移**（含超时/取消/驳回等隐式分支）。」

### P10 权限 / 数据归属模型 ⭐ 条件命中（需求含"只看本组织/本部门"）
- **机械信号**：需求写"按组织机构/只能看本 XX 的数据/本部门可见"，但组织模型、归属字段、隔离维度没定义。
- **为什么致命**：决定数据权限注解与查询过滤条件（RuoYi 系 DataScope/`@RequiresPermissions`），漏问则编码期瞎猜权限。
- **追问模板**：「'本组织机构'的**判定字段**是什么？`<数据>` 的归属按**创建人所属部门/公司**还是其它？多组织之间如何隔离（完全隔离 / 上级看下级）？」

## 增长回路（经验型资产，越用越准）

**每当真实开发/测试/验收提出一个本库没追问到的坑**，就把它抽象成新模式加进本库：
1. 记录原始疑问 + 它命中的功能清单具体处（现象/影响）。
2. 抽象出「机械触发信号 + 为什么致命 + 追问模板（候选答案）」，追加为 `P{n}`。
3. 若属跨模块/跨项目通用 → 标 [HARD]，按 ai-dev-workflow"经验记录与回流"渠道沉淀（可随 skill 版本发布）。

目标：让"这个功能该问什么"从依赖 AI 临场发挥，变成 jee-forge 可复用、可累积的能力。
