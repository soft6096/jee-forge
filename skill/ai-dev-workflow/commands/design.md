# 技术方案（Design）

为功能清单中的某个功能项生成技术方案。**按类型列选模板组合**（3.0 通用骨架 + 类型模板），无需手动指定。

## 输入

- 功能清单（`docs/<模块名>V<版本号>-<YYYYMMDDHHMMSS>/1.1-功能清单.md`）—— **类型路由的依据**
- 项目约束（`docs/<模块名>V<版本号>-<YYYYMMDDHHMMSS>/2.1-项目约束.md`，目录名见 1.1 产物）
- 规范 skill（按需加载）：设计 DDL/表/索引时加载 **database-standards**；设计 Controller/Service 接口分层时加载 **java-code-standards**

## 模板选择（核心逻辑）

1. 在功能清单中查找目标功能项（按名称或编号）
2. 读取该功能项的**类型列**，选模板组合——**类型 → 模板映射见 `templates/3.0-技术方案-通用骨架.md` 的"类型导航表"（单一事实源）**：

| 功能清单类型列 | 模板组合 |
|---|---|
| `Controller` / `Listener` / `Job` | `3.0-技术方案-通用骨架.md` + 对应类型模板（3.1/3.2/3.3，四段差异见 3.0 导航表） |
| 无入口 | 仅 `3.0-技术方案-通用骨架.md`（配置/工具/纯数据，跳过类型段） |

3. 生成方式：3.0 骨架通用章节（基本信息/验收场景/公共组件识别/注释要求/自检）必填；类型特有内容按对应 3.x 模板四段（入口定义/数据契约/核心逻辑/关注点）填充，合并为**一份完整方案**
4. 若功能清单中找不到该功能项或类型列缺失 → 停下来询问用户，不要自行猜测类型

## 通用要求（所有类型通用）

- **样式**：生成前先读 `templates/00-中间产物-MD样式规范.md`——速览框 / 对齐表格 / mermaid 配色 / callout 统一套用
- 基本信息：功能项编号、优先级、依赖
- **验收场景**：合法 + 非法 + 边界（测试用例蓝本，供第 4 步翻译成测试）
- **接口明细**（Controller）：每个 URL 独立小节，必含入参示例（请求体 JSON）+ 出参示例（成功 / 失败），失败示例与错误码对应
- **数据模型与 SQL**：模块全量 SQL（建表 DDL 含索引/约束 + 初始化数据 + 查询 SQL）写入方案"数据模型与 SQL"章节（3.0 通用章节），**禁止独立 sql 目录**；**所有 SQL 语句必须带注释**——DDL 每列 `COMMENT` + 表级 `COMMENT`，DML/查询 SQL 每条 `--` 注释（用途 + 归属 Mapper 函数 + 关键条件，见 3.0 模板"SQL 全量注释"）
- **接口清单（前后端通用）**：每个 Controller 类型功能项技术方案生成后，同步生成该功能项接口清单 `3.<功能项序号>.2-<功能名>-接口清单（前后端通用）.md`（模板见 `templates/3.4-接口清单-前后端通用.md`）——按功能项聚合 URL / 方法 / JSON 入参 / JSON 出参，后端完成后直接给前端；Listener/Job/无入口功能项跳过（注明"无 HTTP 接口"）
- **注释要求**：类/接口 Javadoc 说明
- **架构自检（公共组件识别）**：见下方独立小节，结果写入方案"公共组件识别"章节
- 横切关注点对照项目约束逐条检查
- 完成标准自检（3.0 通用部分 + 类型模板特有部分）

## 架构自检（公共组件识别，每功能项必做）

防重复代码的关口设在**方案期**，不靠编码期"顺手"（编码约束禁止设计外抽取）：

1. 逐条列出本方案中重复出现的逻辑片段（≥2 处使用点：校验、转换、状态流转、幂等、锁、分页等）
2. 判定抽取类型：
   - 无状态纯逻辑 → 工具类（`common/util/`）
   - 有状态/模板方法/共享生命周期 → 抽象基类（`common/base/`）
3. 写出设计：方法签名 / 继承关系 / 归属包
4. 结果写入技术方案"公共组件识别"章节；无重复逻辑则写"无"，4.1 拆任务时 Phase 0.5 留空

## 输出

- `docs/<模块名>V<版本号>-<YYYYMMDDHHMMSS>/3.<功能项序号>.1-<功能名>-技术方案.md`（每功能项一份；**功能项序号 = 功能清单功能项表格的 # 列（1、2、3…）**，非需求点 § 编号；**文件名禁止拼接任务 ID（T0xx）/需求点编号/任何额外前缀**）
- `docs/<模块名>V<版本号>-<YYYYMMDDHHMMSS>/3.<功能项序号>.2-<功能名>-接口清单（前后端通用）.md`（Controller 类型功能项：技术方案生成后同步生成该功能项接口清单；Listener/Job/无入口跳过）

## 完成标准（质量闸门）

- [ ] 模板组合选择正确（读功能清单类型列；无入口形态已走"仅 3.0"路径）
- [ ] 通用章节完整：验收场景含合法 + 非法 + 边界，公共组件识别完成，注释要求已写明
- [ ] 类型特有内容按四段（入口定义/数据契约/核心逻辑/关注点）取自对应 3.x 模板
- [ ] 入参/出参/错误码/校验规则无"待定/视情况"；Controller 每个 URL 有独立入参示例（请求体 JSON）+ 出参示例（成功/失败）
- [ ] 数据模型与 SQL 章节完整：模块全量 SQL（建表 DDL 含索引/约束 + 初始化数据 + 查询 SQL）在技术方案内，**所有 SQL 带注释（DDL 每列 COMMENT + DML/查询 SQL 每条 `--` 用途注释）**，无独立 sql 目录
- [ ] 同模块每个 Controller 功能项方案生成后已产出 `3.<功能项序号>.2-<功能名>-接口清单（前后端通用）.md`（URL / 方法 / JSON 入参 / JSON 出参，失败示例与错误码对应），内容与方案一致；无 HTTP 接口功能项已注明跳过
- [ ] 类型特有横切关注点已写明（Controller→权限事务 / Listener→幂等死信 / Job→防重入批处理）
- [ ] 文档含速览框 + 对齐表格 + mermaid 图（配色用统一主题变量）+ 处理步骤编号
