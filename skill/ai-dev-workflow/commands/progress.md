# 模块进度与接续断点（progress）

## 定位

流程产物 + 人工闸门会产生"做了一半的模块"。跨会话 / 换人接手时，靠本命令快速恢复现场：读模块目录的 `00-进度.md`，报告状态与断点，从断点续跑。

## 执行

1. `ls docs/` 定位模块版本目录（`<模块名>V<版本>-<时间戳>/`）；找不到 → 提示先走"开发场景判定"（1.1 建目录时生成 00-进度.md）。
2. 读取 `docs/<模块>V<版本>-<时间戳>/00-进度.md`（无该文件 → 可先用模板 `templates/00-进度.md` 补建，据已有产物填状态）。
3. 向用户报告：
   - 每步产物状态（✅ 已确认 / 🔲 待办 / ⏸ 断点）
   - **当前断点**（停在哪个步骤、等什么输入）
   - 产物完整性核对：对照 00-进度.md 实际 `ls` 检查产物文件是否都在（缺文件 = 上一会话未落盘，先补）
4. 询问是否从断点续跑 → 用户确认后从断点对应的命令/动作继续。

## 规则（禁止）

- 有 00-进度.md 且显示未完成 → **禁止从 1.1 重跑**，必须从断点续跑
- 迭代/改逻辑仍先遵守 0.8（进度只恢复流程位置，不替代产物同步）
- 用户说不清哪个模块 → 列 docs/ 目录让用户选，不猜

## 输出

- 现场报告（会话内展示；如需留档写回 00-进度.md"变更记录"）
- 续跑动作从当前断点开始

## 完成标准

- [ ] 模块版本目录已定位，00-进度.md 已读取（缺失已按产物补建）
- [ ] 产物完整性已核对（缺文件已提示）
- [ ] 断点与下一步已向用户展示并确认
- [ ] 续跑不越过断点前的确认闸门
