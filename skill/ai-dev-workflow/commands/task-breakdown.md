# 任务拆解

根据技术方案 md，拆解为可独立实现、可独立验证的任务清单。

## 输入

- 第③步的技术方案 md
- 项目约束（`docs/<模块名>V<版本号>-<YYYYMMDDHHMMSS>/2.1-项目约束.md`，目录名见 1.1 产物）

## 执行

1. 按类型套用模板 `templates/4.1-任务拆解.md` 的任务结构：

- **Controller**：Phase 0 数据层 → Phase 0.5 公共组件 → Phase 1 Service → Phase 2 Controller → Phase 3 验证 → Phase 4 收尾
- **Listener**：Phase 0 数据层 → Phase 0.5 公共组件 → Phase 1 消费逻辑实现 → Phase 2 集成 → Phase 3 收尾
- **Job**：Phase 0 数据层 → Phase 0.5 公共组件 → Phase 1 执行逻辑实现 → Phase 2 集成 → Phase 3 收尾
- **无入口**（配置/工具，技术方案第零段判定）：Phase 0 数据层 → Phase 0.5 公共组件 → Phase 1 核心逻辑 → Phase 2 验证 → Phase 3 收尾（跳过 Controller/集成）

> Phase 0.5 公共组件：技术方案"公共组件识别"章节有内容才拆（先落地公共组件，供后续 Phase 复用），无重复逻辑则整 Phase 留空，注明"无公共组件"。

2. 每个任务格式：`[ID] [P?] [Phase] 描述（文件路径 + 验收方法）`
   - `[P]` = 可并行（不同文件、无依赖）
   - **完成标志（必填）**：每个任务的 验收 落成一行**可独立判定**的验证（命令/curl/日志关键字即可判定，无需上下文；禁止"实现 XX"这类判不了对错的描述）——无上下文的新 subagent / 分批编码时靠它判定任务完成

## 输出

`docs/<模块名>V<版本号>-<YYYYMMDDHHMMSS>/4.1.<功能项序号>-<功能名>-任务拆解.md`（**每功能项一份**；功能项序号与 3.x 技术方案一致，如功能项 6 → `4.1.6-前台商品列表与详情-任务拆解.md`；文件名禁止拼任务 ID）

## 完成标准

- [ ] 每个任务有文件路径 + **可独立判定的完成标志**（命令/curl/日志关键字即可判定；纯转发等无需单独验证的任务也写明完成标志）
- [ ] 技术方案的验收场景已作为逐任务完成标志/验证依据（无遗漏）
- [ ] 技术方案"公共组件识别"已翻译成 Phase 0.5 任务（无重复则注明）
- [ ] 依赖顺序正确（Phase 0/0.5 完成后才进 Phase 1）
