# 需求入口整形（req-intake）

## 定位

**开发场景判定之后、1.1 `/feature-list` 之前的可选前置闸门**。

职责**不是**拆功能项（那是 1.1 的活），而是把"原始需求文档"整理成**可直接进入 1.1 的模块级需求**：

- 原始文档可能横跨多个模块、体量超大、还混杂前端等内容 → 一次性硬塞给 1.1 会拆漏、且没人能一次确认一份巨型功能清单
- 本步先按模块切分（边界人拍板）、每个 Java 模块产出一份独立的需求 md（含来源追踪，可回溯原始文档）、人确认一轮——**从源头防需求缺失**

## 触发判据（任一命中 → 执行本命令；都不命中 → 声明跳过）

| 判据 | 说明 |
|---|---|
| 跨多模块 | 需求文档覆盖多个业务模块（订单+商品+用户…），无法用单一模块版本目录承接 |
| 超大文档 | 篇幅大到无法一次性"逐节回读核对"（req-gate 对着整份大文档会漏） |
| 混栈内容 | 混杂前端页面/App/小程序/其他语言服务端等非 Java 服务端内容 |

单模块、纯 Java、体量可控的需求 → **跳过本命令，直接进入 1.1**（本命令不增加小需求负担）。

## 非 Java 服务端需求处理（硬规则，不改）

- **一律直接忽略**：不拆、不列入构成清单、**不产任何文件**（不生成前端需求 md、不列承接方、不建议工具）
- 只在《需求构成清单》最末用一句话注明："已忽略非 Java 服务端部分"，**不展开**

## 输入

- 原始需求文档（可能跨模块 / 超大体量 / 混杂非 Java）
- 开发场景判定结论（老项目迭代：先有 `docs/0.5-存量代码扫描.md`；某模块已有历史产物：该模块 1.1 前仍须先走 0.8）

## 执行

1. **触发判定**：按上表判定。不命中 → 输出结论"单模块纯 Java，跳过 req-intake，直接进 1.1"并结束。
2. **忽略非 Java 部分**（按硬规则，不列清单不产文件）。
3. **识别 Java 模块边界**（AI 提议 + 给出依据，禁止 AI 独自拍板）：
   - 依据：业务域归属、文档章节结构、功能聚类、接口/数据依赖关系
   - 边界拿不准 → 作为待确认项提交给用户，不猜
4. **模块构成清单（人确认闸门 1）**：
   | 模块 | 切分依据 | 覆盖原文章节 | 与其他模块依赖 | 建议开发顺序 |
5. **逐模块生成「模块需求 md」**（每 Java 模块一份，模板见 `templates/0.9-模块需求-模板.md`），每份包含：
   - 模块范围（做什么 / 不做什么）
   - **来源段落追踪**：拆出的每条内容标注原始文档章节（如 §3.2、表格区 7.3.2），链回原始文档，防"拆模块时整段漏进/漏出"
   - 需求点初拆提示（为 1.1 打底，不在此展开成功能项）
   - 验收基线（本次以哪份文档、哪个版本为准 + 文档外的口头补充需求记录）
   - 跨模块接口/数据依赖
   - 假设与待澄清标记（交后续 1.3）
6. **跨模块依赖与顺序**：汇总模块间依赖，给出推荐开发顺序（被依赖模块先行）。
7. **人确认一轮（确认闸门 2）**：展示构成清单 + 各模块需求 md，确认：
   - 模块边界/范围是否正确
   - 来源追踪是否完整（无整段漏掉）
   - 开发顺序是否合理
   - 全部确认后才允许各模块各自进入 1.1

## 输出（落盘）

`docs/req-intake-<YYYYMMDDHHMMSS>/`（批次级目录，非模块版本目录）：

- `0.9-需求构成清单与确认.md`（模板 `templates/0.9-需求入口整形.md`）
- `<模块名>-模块需求.md`（每 Java 模块一份，模板 `templates/0.9-模块需求-模板.md`，供该模块 1.1 作为输入引用）

## 完成标准

- [ ] 触发判据已判定且有明确结论（命中哪条 / 为何跳过）
- [ ] 非 Java 服务端部分已忽略（仅清单末句注明，未列清单、未产文件）
- [ ] 模块切分边界**经人确认**（无 AI 自行拍板）
- [ ] 每份模块需求 md 含：模块范围 + **来源段落追踪** + 验收基线 + 跨模块依赖
- [ ] 模块间依赖与推荐开发顺序已汇总
- [ ] 构成清单 + 各模块需求 md **已向用户展示并获确认**
- [ ] 确认后各模块才进入 `/feature-list`（1.1）；模块已有历史产物 → 1.1 前先 `/change-impact`（0.8）

## 进度记录（00-进度.md）

本步骤产物经人确认后，同步更新模块版本目录 `docs/<模块名>V<版本>-<时间戳>/00-进度.md`：

- 对应步骤行 → `✅ 已确认`；「当前断点」→ 下一步骤；「变更记录」追加一行（日期/更新人/说明）
- 模块目录尚未创建（0.0 / 0.5 / 0.9 req-intake 等前置阶段）→ 跳过；1.1 建目录时创建 `00-进度.md` 并据已有产物回填
