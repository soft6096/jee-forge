# AI 编码

按任务拆解.md 顺序实现代码，目标：**让全部测试变绿**。

## 输入

- 第④步的任务拆解.md + 红色契约测试
- 项目约束（`docs/<模块名>V<版本号>-<YYYYMMDDHHMMSS>/2.1-项目约束.md`，目录名见 1.1 产物）
- 技术方案（作为实现依据）

## 执行规则（硬性约束，不可协商）

```
1. 测试文件是验收标准：禁止修改断言、禁止删除测试、禁止 @Disabled
2. 严格按 Phase 顺序：先数据层 → 再公共组件（0.5）→ 再业务 → 再接口/消费/调度
3. 必须遵守《项目约束》的全部规则（逐条对照，含"注释规范"与"公共组件规范"章节）
4. **生成的代码必须遵守规范 skill 约定**：写任何代码前先加载对应规范（Java → java-code-standards + comment-standards；SQL/表/MyBatis-Plus → database-standards（简单查询用 Wrapper 禁 XML；复杂/手写 SQL 一律 XML；禁注解 SQL）；pom/依赖 → build-standards（springdoc/knife4j、logback 依赖规则），触发矩阵见 SKILL.md）；**各 skill 按其加载矩阵精确到单文件加载，禁止整目录读入（防止规范挤占编码上下文）**，生成物不符合规范即不合格、需返工
5. 每个任务完成后独立提交（commit message = 任务 ID + 描述）
6. 测试红时先排查实现，禁止"改测试迁就实现"
7. 不实现任务拆解.md 之外的东西（不做"顺手优化"）；Phase 0.5 列出的公共组件必须实现并被复用点调用/继承。编码中发现设计外的重复逻辑：不擅自抽取，在该处注释 `// TODO(收敛): 与 Xxx 重复，待抽公共`，由第⑤步验收统一处理
8. 写代码时同 pass 生成注释（内容从技术方案派生，禁止事后补/编造），遵守注释规范；**全量注释，禁止大段代码无注释**（存量适配模式同样适用，不因老项目注释稀疏豁免）
9. **写代码时同步生成日志**（遵守日志规范，见 java-code-standards `00-common/04-logging-standards.md`）——全类 @Slf4j、入口记入参摘要+耗时、关键业务节点记 INFO、异常记 ERROR 带堆栈（**该加日志的地方必须加**，存量适配模式同样适用，不因老项目日志稀疏豁免）；收尾阶段核对注释、日志、权限、事务、幂等、防重入
10. **编码完成即停，不自行执行全量规范核对**：本步职责 = "让测试绿 + 逐任务独立提交 + 编码中自查（注释/日志/权限/事务/幂等/防重入，见约束 8/9）"。**全量规范核对（全部核对项（无级别之分，含方法级注释/日志全覆盖））不属于编码 Agent 职责**——由 **5.2 `/check-standards` 独立核对**（防"自己核自己"骗绿）。编码完成后停下并报告，**禁止自行声称"已通过规范核对"、禁止跨过 5.2 直接进入验收**（5.3 `/accept` 前置检查 `5.2.<功能项序号>-<功能名>-规范核对报告.md`，不存在即拒绝执行）
```

## 输出

- 通过测试的代码（每个任务独立 commit）
- 测试结果汇总（通过/失败）
- 完成报告（明确"编码完成，待 5.2 `/check-standards` 规范核对"——**不输出规范核对报告，那是 5.2 的产物**）

## 完成标准

- [ ] 全部测试绿
- [ ] 未修改任何测试文件（断言/用例）
- [ ] 遵守项目约束全部规则（含注释规范 + 公共组件规范）
- [ ] Phase 0.5 公共组件已实现，使用点已复用（无自留副本、无新增重复代码）
- [ ] 每个任务独立提交
- [ ] 编码完成已停下报告，未自行执行全量规范核对、未跨过 5.2（规范核对由 `/check-standards` 独立执行并产出 `5.2.<功能项序号>-<功能名>-规范核对报告.md`，人确认后才进入 5.3 `/accept`）
