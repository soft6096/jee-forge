# 关键规范自动核对（Check Standards）— 5.2 强制节点

**定位：5.1 编码完成后的强制独立节点，始终执行。** 编码 Agent 不自行执行全量核对（防"自己核自己"骗绿），由本节点独立核对并产出 `5.2.<功能项序号>-<功能名>-规范核对报告.md`；**报告是注释/日志全覆盖的唯一兜底。5.3 /accept 已改为用户可选（默认不执行），本节点不再因"缺 5.2 报告"拒绝出 5.3（旧 5.3→5.2 前置自锁已废除）**。

规范条目多、分散在多个 skill，AI 编码可能漏执行。本命令加载 **check-standards** skill，**优先跑 `scripts/check_standards.py` 机械扫描产出（无 Python 回退 grep/ast-grep）**，逐项核对关键规范，**禁止凭记忆答 ✅**。

> [!IMPORTANT] 本命令已独立为 **check-standards** skill
> 完整检查清单（全部核对项（无级别之分，含方法级注释/日志全覆盖） + `scripts/check_standards.py` 机械核对脚本（无 Python 时回退标准 grep/ast-grep 指令） + 判定标准 + 用户确认闸门）见 **check-standards** skill 的 SKILL.md。
> 执行本命令时：**加载 check-standards skill**——57 项概览见其 SKILL.md，**逐项的完整判据与手工指令在 `references/checklist.md`**（正常流程跑脚本即可，脚本输出自带 `judgment` 判据摘要，无需读全表）。

## 执行步骤

0. **先矫正产物命名与路径**（执行 check-standards skill「第 0 步」）：扫描 docs/ 中间产物——技术方案应 `3.<功能项序号>.1-<功能名>-技术方案.md`、接口清单 `3.<功能项序号>.2-…`、规范核对报告 `5.2.<功能项序号>-<功能名>-规范核对报告.md`、需求覆盖报告 `5.3.<功能项序号>-<功能名>-需求覆盖报告.md`（功能序号与 3.x 一致）；文件名带任务 ID（T0xx）→ 去；路径不在模块版本目录 → 移入（git mv 保留历史）；改动引用同步更新。矫正清单先向用户确认
1. 加载 **check-standards** skill
2. **先与用户确认处理范围**（**新代码 / 全项目**）——未明确则停下问（**附【AI 推荐】：无特殊说明推荐「新代码/本轮改动」+ 理由**），**禁止默认全量扫**（老项目尤其要问）
3. 按 skill「模式判定」判模式（标准 / 存量适配，读 2.1 约束 / 0.5 扫描）；**若用户 prompt 明确说"按 check-standards / jee-forge / 本框架 / 本规范"→ 强制标准模式`--mode standard`**（覆盖存量适配）
4. **【可选】格式自动修**：项目 `pom.xml` 含 `spotless-maven-plugin` → **经用户确认**后 `mvn spotless:apply`（自动修格式类）
5. **优先运行 check-standards skill 的 `scripts/check_standards.py`**（机械扫描产出证据；含全部 57 项：#1~#33 语义 + #34~#57 格式·命名·卫生；无 Python → 逐项执行标准检查指令 grep/ast-grep 降级）；模型只处理脚本标 `manual/warn` 的项，每项附证据（文件:行号）
   - **范围用默认（只扫本次改动）**：本节点扫的就是 5.1 刚生成的代码 → 直接 `--project <项目根>` 即可（脚本默认只扫 git 改动文件，报告/stderr 会注明「如需全量请加 `--all`」）；无 git 改动时脚本自动回退全项目并在报告写明。
   - **⚠️ 不要在 AI 流程里传大范围 `--path`**：`--path <模块根>`／`--path src/main/java` 这类会把整模块存量文件全扫一遍（几百上千个文件），又慢又把存量历史违规混进本次核对结论；确需限定目录就传**本次真正改动的那一个目录**。全量体检/看存量问题才用 `--all`。
6. 未执行到位项（含 INFO，不分重要与否）统一向用户确认是否补齐；确认后补齐，并用 `--verify --before <改前>.json --after <改后>.json` 核对（脚本断言：该项已修 + **无任何项回退**，防"改 A 坏 B"）
   - **成本护栏**：脚本运行前会打印「本次范围 N 个文件，预计约 X 秒」；**范围 > 2000 个文件且未显式 `--all` 会直接拒绝（exit 2）**（曾因大范围扫描跑 55 分钟才中止），> 1000 会告警建议改用默认范围
7. 输出《关键规范核对报告》（含**产物矫正记录** + **✅ 已自动修 / ⚠️ 待人工·AI 修** 两栏），落盘 `docs/<模块名>V<版本号>-<YYYYMMDDHHMMSS>/5.2.<功能项序号>-<功能名>-规范核对报告.md`，**向用户展示报告并等待确认（全 ✅ 或 ❌ 已补齐 → 确认通过）——这是本节点的产物闸门；确认后，若本流程需要，再询问用户是否执行 5.3 /accept（5.3 为用户可选、默认不执行）**
