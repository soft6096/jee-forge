# 关键规范自动核对（Check Standards）— 5.2 强制节点

**定位：5.1 编码完成后的强制独立节点，5.3 验收的前置闸门。** 编码 Agent 不自行执行全量核对（防"自己核自己"骗绿），由本节点独立核对并产出 `5.2.<功能项序号>-<功能名>-规范核对报告.md`；**该报告是 5.3 /accept 的硬性输入——报告不存在 → /accept 拒绝执行，返回本节点**。

规范条目多、分散在多个 skill，AI 编码可能漏执行。本命令加载 **check-standards** skill 用 grep/ast-grep 实际扫描产出，逐项核对关键规范，**禁止凭记忆答 ✅**。

> [!IMPORTANT] 本命令已独立为 **check-standards** skill
> 完整检查清单（全部核对项（无级别之分，含方法级注释/日志全覆盖） + 标准 grep/ast-grep 指令 + 判定标准 + 用户确认闸门）见 **check-standards** skill 的 SKILL.md。
> 执行本命令时：**加载 check-standards skill**，按其中检查项清单逐项执行。

## 执行步骤

0. **先矫正产物命名与路径**（执行 check-standards skill「第 0 步」）：扫描 docs/ 中间产物——技术方案应 `3.<功能项序号>.1-<功能名>-技术方案.md`、接口清单 `3.<功能项序号>.2-…`、规范核对报告 `5.2.<功能项序号>-<功能名>-规范核对报告.md`、验收报告 `5.3.<功能项序号>-…`（功能序号与 3.x 一致）；文件名带任务 ID（T0xx）→ 去；路径不在模块版本目录 → 移入（git mv 保留历史）；改动引用同步更新。矫正清单先向用户确认
1. 加载 **check-standards** skill
2. 按 skill「模式判定与核对依据」先判模式（标准 / 存量适配，读 2.1 约束 / 0.5 扫描）
3. 逐项执行标准检查指令（grep/ast-grep），每项附证据（文件:行号）
4. 未执行到位项（含 INFO，不分重要与否）统一向用户确认是否补齐，确认后补齐并重跑
5. 输出《关键规范核对报告》（含**产物矫正记录**），落盘 `docs/<模块名>V<版本号>-<YYYYMMDDHHMMSS>/5.2.<功能项序号>-<功能名>-规范核对报告.md`，**向用户展示报告并等待确认（全 ✅ 或 ❌ 已补齐 → 确认通过），确认后才可进入 5.3 /accept**——这是本节点的产物闸门

## 完成标准

- [ ] 已矫正产物命名与路径（docs/ 中间产物符合 3.x.1/3.x.2/5.2.x/5.3.x 规范，无任务 ID 前缀，路径在模块版本目录；矫正清单已确认）
- [ ] 已加载 check-standards skill 并按其清单逐项核对（全部核对项（无级别之分））
- [ ] 每项附证据（文件:行号）；未到位项已向用户确认后补齐 / 标注"需人工核对"（不静默吞掉）
- [ ] 报告已落盘 `docs/<模块名>V<版本号>-<YYYYMMDDHHMMSS>/5.2.<功能项序号>-<功能名>-规范核对报告.md`
- [ ] 已向用户展示报告并获确认（本节点产物闸门），确认后才进入 5.3
