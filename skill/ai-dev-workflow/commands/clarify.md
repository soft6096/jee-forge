# 澄清（Clarify）

对功能清单逐项盘问四类问题：**歧义、入口形态与复杂度、边界用例、依赖**，并**逐项裁决 1.2 需求质量核对（/req-gate）交来的矛盾/术语 🔲 项**，输出澄清问题清单，由人确认后补充进功能清单。

## 输入

- 第①步的功能清单（`docs/<模块名>V<版本号>-<YYYYMMDDHHMMSS>/1.1-功能清单.md`，目录名见 1.1 产物）
- **1.2 需求质量核对产物**（`docs/<模块名>V<版本号>-<YYYYMMDDHHMMSS>/1.2-需求质量核对.md`，矛盾/术语 🔲 项在此裁决）
- 原始需求文档（歧义时回溯核对）

## 执行

0. **先扫描追问模式库（机械信号 → 命中必问）**：加载 `docs/追问模式库-Java.md`，逐条对照其机械触发信号扫描功能清单（字段/状态/动作/权限表述）——命中即生成追问，不许自己选答案；同一字段多条命中只出优先级最高一条；**1.2（req-gate）已裁决/已标 🔲 的项直接承接，不重复问**。模式库产生的追问 + 下方四类盘问合并成同一份问题清单。

1. 逐功能项盘问四类问题：

**① 歧义（Ambiguity）— "没说清"**
- 找模糊词："等"、"相关"、"适当"、"尽快"、"按需"
- 找未定义字段/参数（如"用户管理"没列具体操作）
- 找不可验证的验收标准（"实现 XX 功能" → 问"怎么算完成"）
- 例：`订单取消` → 问：**已发货的订单能取消吗？软删还是硬删？**

**② 入口形态与业务复杂度（第零段判定前置，方案错判的根因在这）**
- 入口形态：HTTP 接口 / MQ 消费 / 定时调度 / 无入口（配置/工具）？复合形态（如 HTTP + MQ 触发）？
- 业务复杂度：纯 CRUD 转发 / 复杂（多表写、状态流转、算法、并发）？
- 跨功能项规则：状态机是否横跨多入口？归属哪个功能项定义？
- 例：`订单支付回调` → 问：**是 MQ 消费还是 HTTP 回调？幂等靠唯一键还是状态位？**

**③ 边界用例（Edge Cases）— "没想过的极端情况"**
- 重复提交（幂等）—— 重复点取消按钮？
- 并发操作 —— 两人同时改同一订单？
- 空值/超长/非法格式 —— 手机号 20 位？
- 状态流转缺失 —— 从"已取消"能直接到"已支付"吗？
- 例：`订单取消` → 问：**重复取消请求返回什么？部分发货状态能取消吗？**

**④ 依赖（Dependencies）— "没标注的关联"**
- 功能间依赖是否完整标注
- 外部系统/第三方依赖（库存服务？支付网关？）
- 数据依赖（引用表存在吗？外键关系？）
- 例：`订单创建` → 问：**依赖库存服务吗？库存扣减失败回滚策略？**

2. 按模板 `templates/1.3-澄清问题清单.md` 生成问题清单，每个问题：涉及功能项 + 问题 + **AI 建议默认值** + 状态（待确认）

3. 问题清单交给人确认：逐项采用 AI 默认值或修改，状态改为"已确认"

4. 根据确认结果**更新功能清单**：补"边界/风险"列、完善依赖列、澄清歧义字段、**更新类型列与业务复杂度判定（第零段输入）**；1.2 交来的矛盾/术语 🔲 项裁决结果同步回写 1.2 产物与功能清单

## 输出

- `docs/<模块名>V<版本号>-<YYYYMMDDHHMMSS>/1.3-澄清问题清单.md`（问题清单，状态列无"待确认"残留；文件名带 1.3 编号，与流程步骤对应）
- 更新后的 `docs/<模块名>V<版本号>-<YYYYMMDDHHMMSS>/1.1-功能清单.md`

## 完成标准

- [ ] **追问模式库已扫描**（docs/追问模式库-Java.md）：命中信号已全部生成追问（未自己选答案）；同一字段重复命中已按优先级去重；无规格性字段/状态/权限可命中时注明"模式库无命中"
- [ ] 每个功能项无未确认的歧义（模糊词已澄清）
- [ ] 每个功能项的边界用例已列出（合法/非法/边界三态）
- [ ] 依赖完整标注（功能间 + 外部系统）
- [ ] **1.2 需求质量核对交来的矛盾/术语 🔲 项已全部裁决**（无残留；模式库不重复追问已裁决项）
- [ ] 问题清单状态列无"待确认"残留
- [ ] 功能清单已更新（边界/风险列 + 依赖完善）
