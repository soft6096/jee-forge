# 需求覆盖报告（防漏做核对）

当前功能项代码实现完成后，**由独立步骤**（非编码 Agent 自评）逐需求点回读核对代码，输出**需求覆盖报告**——证明"需求点的每一项都有落点或明确缺口"。

> 定位：这是**防漏做**闸门，**不是"验证通过"**。可机器判定的结构项附证据；语义/行为项只标注"静态未验证，需按需行为验证"，**禁止打 ✅**。需要运行时行为验证（接口真的能调通/事务并发行为正确）时，**按需**用 `test-workflow` 技能（`/gen-test`）真实调用接口，不阻塞本报告。

## 输入

- `1.1-功能清单.md`（本功能项 + 承接需求点 + 验收标准 GIVEN-WHEN-THEN）
- `3.<功能项序号>.1-<功能名>-技术方案.md`（验收场景三态：合法 / 非法 / 边界）
- `3.<功能项序号>.2-<功能名>-接口清单（前后端通用）.md`（Controller 类型；URL / 方法 / 入参 / 出参）
- 5.1 已实现代码（`src/main/java/...`）
- **`docs/<模块名>V<版本号>-<YYYYMMDDHHMMSS>/5.2.<功能项序号>-<功能名>-规范核对报告.md`（条件输入：5.2 本就必做、正常已存在；执行本步前顺带确认，不存在 → 提示先补做 5.2。**5.2 不再是拒绝出报告的硬闸门，因 5.3 已改为用户可选**）**

## 执行

0. **执行前询问（本节点默认不执行，由用户选择）**：向用户提问「本功能项是否执行需求覆盖核对（5.3）？」，附【AI 推荐】（推荐项不加勾选框）：
   - **【AI 推荐】完整模块开发 / 新增 Controller 功能项 → 执行** —— 理由：这是唯一的"防需求漏做"闸门，1.1 拆漏、端点/字段缺失只有回读代码才能发现；跳过 = 漏做静默进上线
   - 轻量模式 / quick-change 增量轻量 / 仅 Listener·Job·配置类 → **可跳过**（价值低：入口类默认还标"未验收"；回归证据 + 5.2 已能兜住大部分风险）
   - **用户选择跳过 → 不生成报告**，在对话内给三行结论（逐需求点是否都有落点 / 疑似缺口 / 未覆盖入口），并在模块进度文件把 5.3 行标 `⏭ 已跳过（经确认）` + 变更记录追加一行；**不得把跳过当作"已核对通过"声称**
   - 用户选择执行 → 继续下面第 1 步

1. **规范核对确认（非拒绝闸门）**：`ls docs/*/5.2.*-*.md` 确认 `5.2.<功能项序号>-<功能名>-规范核对报告.md` 已由 `/check-standards`（5.2 节点，本就必做）产出：
   - 报告存在但含未解决 ❌ → 提示先回 /implement 补齐 + 重跑 /check-standards，再回来出本报告
   - 报告不存在 → 提示补做 5.2（5.2 是注释/日志全覆盖的唯一兜底，不应缺）；**用户明确坚持先出 5.3 → 报告内标注"5.2 报告缺失，规范项未核"，不拒绝执行**（旧版"无报告即拒绝验收"的自锁已废除）

2. **逐需求点核对（需求 → 代码，防漏做）**：读 1.1 功能清单与本功能项验收标准，逐条回读代码定位落点：
   - 每个需求点 / 验收点 → 找对应实现 → 记 **`代码位置(file:line)`** 或 **`未找到（缺口）`**
   - **证据必须落到 `file:line`**（类 / 方法 / 校验 / 错误码 / DDL），禁止凭方案或凭记忆写"应该实现了"

3. **反向核对（代码 → 需求，防多做/偏做）**：遍历本功能项目标范围内的代码，找出"**需求没要求、代码里却有**"的东西（自创字段 / 额外端点 / 超出范围的逻辑）→ 记入"反向核对"表，标"需求未要求"待确认。

4. **两类结论分列（严禁混淆）**：
   - **① 可机器验证**（端点 / 字段 / 校验规则 / 错误码 / DDL 是否存在）：附证据 `file:line`，判 `✅ 已实现` / `❌ 未找到`。
   - **② 语义 / 行为**（业务规则是否正确、状态流转 / 事务 / 并发行为是否符合预期）：**显式标注"静态未验证，需按需行为验证"**，**禁止打 ✅**（静态核对无法证明运行时行为）。

5. **覆盖边界如实标注**：

   | 入口 | 本报告处理 |
   |---|---|
   | Controller（HTTP） | 逐需求点核对（可机器验证项附证据 + 语义项标未验证） |
   | Listener（MQ） | 默认标"**未验收**"（缺投递/触发手段），**不阻塞收尾** |
   | Job（定时） | 默认标"**未验收**"（缺手动触发手段），**不阻塞收尾** |
   | 无入口（框架回调 / 启动期 / 纯工具） | 标"**未覆盖**"，如实注明 |

6. **缺口闭环**：未找到项 → 产出**缺口清单**（缺口 + 对应需求点 + 处理建议）→ 向用户展示确认 → 追加任务回 `/implement` 补齐，或**人工确认豁免**（写明理由，禁止拿豁免当借口）；Listener/Job"未验收"项**不阻塞**收尾。处理完成后回本步更新报告。

## 输出

- **用户选择执行**：`docs/<模块名>V<版本号>-<YYYYMMDDHHMMSS>/5.3.<功能项序号>-<功能名>-需求覆盖报告.md`（模板 `templates/5.3-需求覆盖报告.md`；功能项序号与 3.x 技术方案一致）
- **用户选择跳过**：**不落盘报告**；对话内三行结论 + 模块进度文件 5.3 行标 `⏭ 已跳过（经确认）`（含日期与理由）

## 完成标准

- [ ] **已向用户询问是否执行 5.3（附【AI 推荐】，推荐项不加勾选框），选择结果已记录**（执行 → 本报告；跳过 → 模块进度标 `⏭ 已跳过（经确认）` + 对话内三行结论；**禁止把跳过谎称成已核对通过**）
- [ ] 5.2 规范核对报告已确认存在（5.2 本就必做）；确实缺失时报告内已标注"5.2 报告缺失，规范项未核"（**不因此拒绝执行，旧自锁已废**）
- [ ] 逐需求点核对表完整：每需求点有 `file:line` 证据或明确"未找到（缺口）"，无凭记忆结论
- [ ] 反向核对完成：需求没要求、代码里却有的内容已列出并标"需求未要求"
- [ ] 两类结论分列：可机器验证项附证据；**语义/行为项标"静态未验证，需按需行为验证"且未打 ✅**
- [ ] 覆盖边界如实：Listener/Job 标"未验收"（不阻塞）、无入口标"未覆盖"
- [ ] 缺口已产出清单并经人确认处理（补齐 / 豁免 + 理由），无静默缺口
- [ ] 报告经人确认后落盘（`5.3.<功能项序号>-<功能名>-需求覆盖报告.md`）

- 对应步骤行 → `✅ 已确认`；「当前断点」→ 下一步骤；「变更记录」追加一行（日期/更新人/说明）
- 模块目录尚未创建（0.0 / 0.5 / 0.9 req-intake 等前置阶段）→ 跳过；1.1 建目录时创建 `通用-模块进度与断点.md` 并据已有产物回填
