# 验收报告（收敛核对）

全部测试变绿后，对照技术方案逐条核对实现，输出**验收报告**。

## 输入

- 第③步的技术方案 md
- 已实现的代码 + 测试结果
- **`docs/<模块名>V<版本号>-<YYYYMMDDHHMMSS>/5.2.<功能项序号>-<功能名>-规范核对报告.md`（前置硬依赖，先检查存在性）**

## 执行

0. **前置检查（硬性闸门）：5.2 规范核对报告必须已存在**——`ls docs/*/5.2.*-*.md` 确认 `5.2.<功能项序号>-<功能名>-规范核对报告.md` 已由 `/check-standards`（5.2 节点）产出且用户已确认通过：
   - **报告不存在 → 拒绝进入验收，提示先执行 `/check-standards` 完成规范核对**（禁止跳过核对直接验收、禁止用"编码 Agent 自查结果"替代）
   - 报告存在但含未解决 ❌（含 INFO，不分重要与否）→ 先追加任务返回 /implement 补齐 → 重新 /check-standards → 再回来验收

1. **引用 5.2 报告结论（不重复全量自动核对）**：加载 `5.2.<功能项序号>-<功能名>-规范核对报告.md`，其 全部核对项（无级别之分，含方法级注释/日志全覆盖）结论为验收核对表基础（禁止凭记忆/自行重扫替代）；人工补核 5.2 报告覆盖不到的质量项。按模板 `templates/5.3-验收报告.md` 生成核对报告，按类型逐条核对：

**Controller 核对**：

| 核对项 | 对照来源 | 常见漂移 |
|---|---|---|
| 接口路径/方法/入参出参 | 技术方案接口清单 | AI 改参数名、漏字段 |
| 校验规则 | 技术方案入参校验 | 校验缺失或过严 |
| 表名/字段/类型/索引 | 技术方案《数据模型与 SQL》章节 | AI 自创列名 |
| Service 映射 | 技术方案接口清单 | 调错 Service 方法 |
| 权限/事务 | 项目约束 | 漏 @RequiresPermissions |

**Listener 核对**：队列/路由键/ACK、幂等逻辑、死信/重试、消息体校验
**Job 核对**：cron/调度、防重入锁、批处理、失败告警
**无入口核对（如适用）**：确无入口形态（非漏写）、核心逻辑/业务规则与方案一致
**注释核对（所有类型必做）**：对照项目约束"注释规范"章节——所有类（DTO/VO/Config 等，仅示例非穷举）类注释齐全、所有变量/字段注释齐全、所有方法（含测试方法）注释齐全（@param/@return 有业务含义）、方法体 ≥2 步有编号步骤注释、无逐行翻译式注释、复杂逻辑有 // WHY:、注释与代码一致（防编造）
**公共组件与重复代码核对（所有类型必做）**：对照技术方案"公共组件识别"小节 + 项目约束"公共组件规范"章节——Phase 0.5 公共组件已实现、使用点已复用无自留副本、全模块扫描无 ≥2 处相同/相似方法体、编码期 `// TODO(收敛)` 重复标记已处理。发现重复代码 → 追加"抽公共组件 + 改使用点"任务 → 返回 /implement

2. **quickstart 调通（必做，缺证据 = 验收不通过）**：mock/切片测试不加载完整 Spring 上下文、不连真实库，**测试绿 ≠ 能启动**。按模板 `templates/5.3-验收报告.md` 的"quickstart 调通证据"章节执行：
   - 环境准备：建库建表（执行技术方案《数据模型与 SQL》章节 DDL，或累计的 schema.sql 初始化脚本）、中间件启动、配置就位
   - **老项目场景（存量适配模式）**：老项目已接入的中间件与基础设施（数据库/缓存/消息队列/定时调度/文件存储/搜索引擎等，完整清单以 `0.5-存量代码扫描.md` 中间件清单为准）**直接复用老项目已有账号配置**连环境，确保流程能过、quickstart 成功；**老项目没有这些账号信息 → 停下来向开发人员索取，禁止编造/凭印象填写**
   - **全新构建**：`mvn clean package`（禁止用历史 jar/class 产物，旧产物可能含过期配置——真实事故：源码配置已修但 jar 未重打，启动即炸 `Unsupported character encoding 'utf8mb4'`）
   - 真实启动：记录 `Started ... in x.xxx seconds` + Tomcat 端口日志
   - 按技术方案"验收场景"逐条 curl 实测（合法 + 非法 + 边界三态），记录请求/期望/实测/结果
   - 调通对数据有污染（改密/删数据）→ 验证后复位

3. 核对出差异 → 追加为新任务（T009…）→ 返回 /implement 继续 → 再跑测试

## 输出

`docs/<模块名>V<版本号>-<YYYYMMDDHHMMSS>/5.3.<功能项序号>-<功能名>-验收报告.md`

## 完成标准

- [ ] **前置检查通过：`5.2.<功能项序号>-<功能名>-规范核对报告.md` 已存在**（/check-standards 产出 + 用户确认）——报告不存在则拒绝验收回 /check-standards
- [ ] 引用 5.2 报告结论（不重复全量自动核对），人工补核质量项
- [ ] 全部核对项 ✅ 或差异已追加任务处理
- [ ] 公共组件核对通过（无重复代码残留）
- [ ] 验收报告无"未解决差异"
- [ ] 人工抽查核心逻辑
- [ ] **quickstart 调通证据齐全（必填）**：全新构建 + 真实启动日志 + 按验收场景逐条实测（三态全覆盖），证据落盘在验收报告中；仅测试绿不算通过
- [ ] 功能清单逐项打勾，确认覆盖
