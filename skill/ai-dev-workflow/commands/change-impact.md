# 迭代变更影响分析（change-impact）

在**已有模块（docs/ 下已存在该模块历史版本产物目录）上改逻辑 / 迭代新需求**时必做。核心思想：**先找到旧中间产物，从源头（1.1 功能清单）开始一步步同步更新产物，最后才改代码**——不溯源就改码，产物与需求/代码失同步，越积越乱。

## 触发场景

- 用户说"把 XX 的逻辑改一下 / 调整一下 XX 功能 / 在 XX 模块上新增个 XX"，而该模块 **docs/ 下已存在 `<模块名>V<版本>-<时间戳>/` 产物目录**（如 `docs/产品管理模块V1.0.0-20260825172102/`）
- 同模块已有本流程产物（1.1 功能清单 / 3.x 技术方案 / 接口清单），要在其基础上迭代
- **判定兜底**：拿不准该模块是否已有产物 → 先 `ls docs/` 查同名模块目录；有 → 走本命令；无 → 回"开发场景判定"按 0.5/1.1 处理，**禁止假装没有旧产物直接开新目录**

## 输入

- 本次变更描述（用户口述 / 变更单 / 新需求文档）
- 模块历史产物目录（`docs/<模块名>V<版本>-<时间戳>/`，可能多个版本，取**最新版**为基准）

## 执行

### 1. 定位历史产物（先找，再比）

`ls docs/` 列出该模块所有历史版本目录，确认**最新版本目录**；读其中：
- `1.1-功能清单.md` → 旧功能项清单（功能项表格：序号/功能项/类型/验收标准）+ 需求点清单
- `3.<功能项序号>.1-<功能名>-技术方案.md` → 旧方案（入口/数据契约/核心逻辑）
- `3.<功能项序号>.2-<功能名>-接口清单（前后端通用）.md` → 旧接口契约
- 有必要时对照实际代码（反查产物与代码是否已漂移）

记录到产物"历史版本定位"章节：目录路径 + 版本号 + 已有哪些产物文件。

### 2. 变更点 → 旧功能项映射（找"相应的地方"）

把本次变更拆成**变更点**（每点一行：改了什么），逐点映射到旧产物：

| # | 本次变更点 | 影响的旧产物（目录+文件） | 影响的功能项（旧序号） | 变更类型 |
| :---: | :--- | :--- | :---: | :---: |
| 1 | 商品列表增加"商品类型"筛选 | 产品管理V1.0.0/3.1.1-商品列表-技术方案.md | #1 商品列表 | 修改 |
| 2 | 商品取消逻辑改为软删 | 产品管理V1.0.0/3.2.1-商品取消-技术方案.md | #3 商品取消 | 修改 |
| 3 | 新增商品批量导入 | —（旧产物无） | — | 新增 |

- 变更类型：**新增**（旧产物无对应）/ **修改**（改动既有功能项的入口/逻辑/字段/接口）/ **删除**
- 每行必须能落到**具体的旧产物文件**；落到不上的"新增"也要明确写"旧产物无对应，需在 1.1 新增功能项"

### 3. 产物同步计划（从源头开始列）

按流程顺序列出**本次要同步的产物链**（先源头后下游，禁止只改代码）：

| 同步顺序 | 产物 | 动作 |
| :---: | :--- | :--- |
| 1 | `新版本目录/1.1-功能清单.md` | 继承旧清单 + 标注变更点（新增功能项/修改功能项验收标准/删除项）；需求覆盖核对同步 |
| 2 | `新版本目录/3.<序号>.1-技术方案.md` | 受影响功能项方案按变更点更新（入口/数据契约/核心逻辑/验收场景） |
| 3 | `新版本目录/3.<序号>.2-接口清单.md` | 受影响接口按变更更新（URL/入参/出参/错误码） |
| 4 | 后续 4.x/5.x | 按变更影响决定是否重建任务拆解/契约测试/编码 |

- 注明**版本目录**：新版本号从变更需求文档/用户确认（如 V1.0.0 → V1.1.0），新目录名 `<模块名>V<新版本>-<新时间戳>`；**旧版本目录保持不动可追溯**
- 明确哪些旧产物**不受影响**（继承即可），避免无谓重写

### 4. 变更影响确认闸门（强制，未确认不得进入 1.1）

向用户展示：历史版本定位 + 变更映射表 + 产物同步计划。**用户确认后**才进入 1.1（`/feature-list`，以本分析为输入，从源头同步新版本 1.1 功能清单）；有异议 → 修正后重新确认。

## 输出

- `docs/0.8-迭代变更影响分析.md`（参考模板 `templates/0.8-迭代变更影响分析.md`；若新版本目录已建则放入新版本目录内，未建则放 docs/ 根，1.1 建目录时移入）

## 完成标准

- [ ] **历史产物已定位**：列出该模块所有版本目录，确认最新版并读取其 1.1/3.x/接口清单（记录路径）
- [ ] **变更映射完整**：本次每个变更点都有对应旧产物（修改/删除）或明确"旧产物无对应，需新增功能项"
- [ ] **产物同步计划已列**：按 1.1→3.x→4.x→5.x 顺序列出受影响产物及动作，注明不受影响（继承）项
- [ ] **版本目录已定**：新版本号已确认（V1.0.0→V1.1.0），旧版本目录不动
- [ ] **变更影响已获人确认**：展示定位/映射/计划，确认后才进入 1.1
- [ ] 未确认前未动任何代码（只读旧产物 + 本产物落盘）

## 进度记录（00-进度.md）

本步骤产物经人确认后，同步更新模块版本目录 `docs/<模块名>V<版本>-<时间戳>/00-进度.md`：

- 对应步骤行 → `✅ 已确认`；「当前断点」→ 下一步骤；「变更记录」追加一行（日期/更新人/说明）
- 模块目录尚未创建（0.0 / 0.5 / 0.9 req-intake 等前置阶段）→ 跳过；1.1 建目录时创建 `00-进度.md` 并据已有产物回填
