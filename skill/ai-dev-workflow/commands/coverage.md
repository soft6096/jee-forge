# 功能覆盖与验收表（模块收尾闸门）

本模块**全部功能项走完 5.2 `/check-standards` + 5.3 `/accept` 后**执行一次，确认无漏做/漏验收/漏收敛；开发中途也可 `/coverage` 随时盘点。**每份 5.3 验收只证明单个功能项对**，本表回答"**整个模块是否每个功能项都闭环了**"。

## 输入

- 本模块 1.1 功能清单（`docs/<模块名>V<版本号>-<YYYYMMDDHHMMSS>/1.1-功能清单.md`）
- 模块版本目录（含全部 3.x / 4.x / 5.2.x / 5.3.x 产物）

## 执行

1. **读功能清单**：读取 1.1 功能清单，列出全部功能项（# + 名称 + 类型），作为表行。
2. **逐项实查（ls + 读结论，禁止凭记忆）**：对每个功能项核实：
   - 3.x 方案：`3.<#>.1-<功能名>-技术方案.md` 是否存在
   - 接口清单：`3.<#>.2-…-接口清单（前后端通用）.md` 是否存在（非 Controller 功能项标 —）
   - 契约测试：`src/test/java/…/Test<功能名>.java`（或对应测试）存在且绿
   - 代码：5.1 已编码（测试绿为证）
   - 5.2 报告：`5.2.<#>-<功能名>-规范核对报告.md` 存在且结论全 ✅（用户已确认）
   - 5.3 报告：`5.3.<#>-<功能名>-验收报告.md` 存在且结论已收敛（Converged，无未解决差异 + quickstart 证据）
3. **填表**：按模板 `templates/5.4-功能覆盖与验收表.md` 生成。**只填 ✓/文件名/一句缺口，不复制证据**。
4. **列缺口 → 再跑清单 → 人确认**：有缺口的功能项 → 汇总到"覆盖缺口与再跑清单"，每项给出建议（追加任务回 /implement → /check-standards → /accept，或人工确认豁免 + 理由），**向用户展示并等待逐项拍板**。
5. **处理 → 复跑**：用户拍板"重新跑"的项 → 追加任务处理 → 处理完成后**复跑本表**直到全功能项 ✅。

## 输出

- `docs/<模块名>V<版本号>-<YYYYMMDDHHMMSS>/5.4.1-<模块名>-功能覆盖与验收表.md`（**单模块流程固定 .1**）
- **多模块需求（0.9 req-intake 拆分）**：各模块目录各一份，按模块构成清单顺序编号：`5.4.<清单序号>-<模块名>-功能覆盖与验收表.md`（如 `5.4.1-订单模块-…`、`5.4.2-售后模块-…`）

## 完成标准

- [ ] 已读 1.1 功能清单，逐功能项列出（无遗漏）
- [ ] 每格为 `ls`/读报告实查结果，非凭记忆（缺什么列了文件名）
- [ ] 缺口全部进再跑清单，每项有建议处理方式
- [ ] 再跑清单已获人逐项确认（重新跑 / 豁免 + 理由）
- [ ] 重新跑项已处理完毕并复跑本表 → **全部功能项 ✅ 才允许标"已收敛（Converged）"**；模块收尾（merge/交付）以本表全绿为前提
- [ ] 本模块 5.4 未收敛前，`通用-模块进度与断点.md` 的 5.4 行保持 ⏸

- 对应步骤行 → `✅ 已确认`；「当前断点」→ 下一步骤（经验沉淀 / git merge 决策）；「变更记录」追加一行（日期/更新人/说明）
- 模块目录尚未创建（0.x 前置阶段）→ 跳过
