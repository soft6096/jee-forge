# 生成验收测试工具

为**已生成**的代码生成一套"真实调用入口"的验收测试工具。**只生成，不自动执行。**

> 用例设计与执行器准则见 **test-workflow** skill（`standards/case-design.md`、`standards/runner-standards.md`）。

## 输入

- 待验证的功能项 / 模块
- `3.<n>.2-<功能名>-接口清单（前后端通用）.md`（URL / 方法 / JSON 入参出参）
- `3.<n>.1-<功能名>-技术方案.md` 的验收场景（合法 / 非法 / 边界）
- 环境信息：base URL、鉴权方式、（事务断言）数据库连接

## 执行

1. **落地执行器**：把 `assets/runner/` 复制到项目 `<模块>/tests/runner/`（已存在则跳过，不覆盖）
2. **生成用例**：按 `standards/case-design.md`，从验收场景三态推导用例，写入 `<模块>/tests/<功能项>.cases.yaml`
   - **核心业务场景优先**；**不做字段取值穷举**（避免用例爆炸）
   - 每个用例含：请求（method / path / headers / body）、前置数据（可选）、期望（status + 关键字段）、断言类型
3. **生成报告骨架**：按 `templates/验收测试报告.md` 输出报告文件头（未执行时为空骨架）
4. **不执行**：提示开发者运行命令，例如：
   ```bash
   python3 <模块>/tests/runner/runner.py --cases <模块>/tests/<功能项>.cases.yaml
   ```

## 覆盖模式

- **HTTP（默认）**：Controller 接口
- **MQ / Job**：仅当用户**显式指定**生成时输出对应用例（需投递 / 触发手段；无手段则在报告中标注"未覆盖"）

## 输出

| 产物 | 路径 |
|---|---|
| 通用执行器 | `<模块>/tests/runner/`（从 `assets/runner/` 复制） |
| 验收用例 | `<模块>/tests/<功能项>.cases.yaml` |
| 验收测试报告 | `验收测试报告-<模块>-<时间戳>.md`（执行后填充） |

## 完成标准

- [ ] 用例覆盖 3.x 验收场景（合法 / 非法 / 边界），核心业务场景齐全
- [ ] 未做字段穷举（避免用例爆炸）
- [ ] 覆盖边界已标注（Listener / Job / 无入口）
- [ ] **未自动执行**（执行权在开发者）
