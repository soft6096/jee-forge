> 使用说明：这是 **test-workflow** 技能（`/gen-test`）的产物模板。由通用执行器运行验收用例后生成；**独立文件**，落盘命名 = `验收测试报告-<模块名>-<YYYYMMDDHHMMSS>.md`。
> 目的：用**真实请求 + 服务端日志**证明"代码能调通、行为符合验收场景"，供开发者定位并让 AI 补齐/修复代码。

## 失败清单（供 AI 定位修复）

### F-1 用例 #2：商品不存在应返回 400，实测 200

| 项 | 内容 |
| :--- | :--- |
| 分类 | `STATUS_MISMATCH` |
| 请求 | `POST /order` body=`{"userId":88,"itemIdList":[99999],"amount":"100.00"}` |
| 期望 | status=400，code=400（商品不存在） |
| 实测 | status=200，body=`{"code":200,"data":{"orderId":1002}}` |
| 服务端日志摘录 | ```INFO ... createOrder userId=88 ...```（未见商品校验分支） |
| 疑似缺口 | 未校验商品是否存在即创建订单；对应验收场景"非法-商品不存在" |
| 修复建议 | Service 层补商品存在性校验，抛 `BusinessException(ITEM_NOT_FOUND)` |

### F-2 用例 #5：失败后应无残留，实测有残留

| 项 | 内容 |
| :--- | :--- |
| 分类 | `DB_ASSERT_FAILED` |
| 请求 | `POST /order`（第 2 步写库失败） |
| 期望 | 查库：该用户订单数 0（回滚） |
| 实测 | 查库：订单数 1（未回滚） |
| 服务端日志摘录 | ```ERROR ... rollback ...``` |
| 疑似缺口 | 事务回滚未生效（`rollbackFor` 缺失 / 异常被吞） |
| 修复建议 | 确认 `@Transactional(rollbackFor = Exception.class)` 与异常传播 |
