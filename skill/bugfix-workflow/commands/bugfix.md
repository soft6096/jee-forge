# Bugfix（缺陷修复 · 产物定位 + A/B/C 分层）

## 输入

- bug 报告：用户原话 / 复现入口（URL、接口、页面、参数）/ 期望 vs 实际 / 报错日志
- 项目现状：老项目先有 `docs/0.5-存量代码扫描.md`（无 → 按 ai-dev-workflow `/legacy-scan` 补）；该模块 docs/ 是否有 ai-dev-workflow 历史产物

## 执行

**0. 前置：记录原话 + 项目模式确认**
- **完整保留用户原话**（先记录再转工程问题，禁止一开始就改写用户问题）
- 确认项目模式与模块产物目录（`ls docs/`，有产物 → 本次产物定位/同步都以它为基准）

**0.5 前置分类（产品口径型？）**
- 问题涉及按钮/页面/文案呈现、角色权限/可见性、默认值/边界状态、生成/保存/下载规则等"该是什么样"的口径 → **先与用户对齐期望口径**，再判定：
  - 期望与冻结合同/产物不符且以新期望为准 → **C 层（口径变更）**：停止本流程，转 ai-dev-workflow（需求变更/0.8）
  - 纯技术错误（报错/接口失败/样式/测试失败/计算结果）→ 继续
- 拿不准 → 问一句"这是产品口径问题，还是纯代码问题？"

**1. 产物定位（用中间产物当地图，别直接翻代码猜）**
- 把 bug 落到：1.1 功能清单对应功能项 → `3.<n>.1-<功能>-技术方案.md`（核心逻辑/验收场景）→ `3.<n>.2-<功能>-接口清单.md`（入参/出参/错误码）
- 无产物 → 按轻量修复处理（无产物可同步；若需规格依据先回 ai-dev-workflow 补产物再修，或与用户确认直接修）

**2. A/B/C 根因分层判定（对照产物，判断错在哪层）**
| 层 | 判定 | 去向 |
|---|---|---|
| A 实现偏离产物 | 3.x 逻辑/验收场景/契约是对的，代码没按它写 | 改代码，产物不动 |
| B 产物逻辑错 | 3.x 逻辑/验收场景/接口清单口径本身与真实期望不符（代码按产物写了但产物就错） | **先改 3.x 对应段 → 改代码对齐** |
| C 需求口径变 | 用户给的是新期望 | **停止 bugfix**，转 ai-dev-workflow（0.8 / 需求变更） |

- 判定依据写入修复单（引用 3.x 哪一段 + 代码哪一处），禁止无依据选层

**3. 按层修复**
- A：直接按产物修正代码（最小改动）
- B：
  1. **轻量修产物**：只改该 bug 涉及的 3.x 段落（核心逻辑/验收场景/接口清单对应行），逐条记入修复单「产物同步记录」（旧表述 → 新表述 + 原因）
  2. 改代码与修正后产物一致（产物为源、代码对齐），最小改动
  3. 检查其它产物是否引用被改段落（1.1/4.1/其它 3.x），受影响 → 同步标注
- C：输出"停止原因 + 建议变更路径"，结束（不进入修复/不写产物伪记录）

**4. 最小修复 + 注释/日志**
- 只改根因相关，禁止顺手优化/重构/无关清理；本次代码全量注释（comment-standards）+ 方法级日志（java-code-standards §1.6）

**5. verify（功能回归）**
- 相关功能回归 + 受影响验收场景抽查（B 层 = 修正后的验收场景）
- 证据：运行日志 / 关键文件:行号（如需运行时行为验证，可显式用 `test-workflow`（`/gen-test`）生成验收测试工具）

**6. 兜底与沉淀**
- 加载 **check-standards** skill 对本次改动核对（逐项附证据），未到位项先向用户确认补齐
- 修复单落盘 `docs/<模块>/bugfix-<YYYYMMDDHHMMSS>.md`（含 **A/B/C 判定 + 产物同步记录**）
- 坑记入 `docs/experience.md`（跨模块通用 → 标 `[HARD]`，人工走家族固化流程）

## 输出

- 修复单 `docs/<模块>/bugfix-<YYYYMMDDHHMMSS>.md`（模板 `templates/bugfix-修复单.md`）
- 代码改动（最小）+ 功能回归证据 + 核对结论；B 层含产物同步记录

## 完成标准

- [ ] 用户原话已保留；产品口径型已前置分类（是 → 已对齐口径；属新期望 → C 转变更）
- [ ] 已复现；已**产物定位**（1.1 → 3.x.1 → 3.x.2）
- [ ] A/B/C 判定明确且写入修复单（C → 已停止，未在 bugfix 内改口径）
- [ ] A：产物未动；B：3.x 对应段已轻量修正 + 产物同步记录 + 代码已对齐；C：已转 ai-dev-workflow
- [ ] 最小改动完成，本次代码全量注释 + 方法级日志
- [ ] 相关功能回归证据（受影响验收场景抽查）
- [ ] `/check-standards` 兜底核对完成
- [ ] 修复单落盘，经验按需写入 docs/experience.md
