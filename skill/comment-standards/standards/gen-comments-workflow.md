# 存量注释补全工作流 (Gen-Comments Workflow)

## 适用范围

为存量代码生成/补全注释时加载。核心原则：**有 spec 走 spec，无 spec 降级为事实注释，猜不出的意图宁缺毋滥**。

## 输入

- 目标代码路径（文件/目录/模块）
- 技术方案 md（存在时自动走 `--from-spec`，否则 `--from-code`）

## 两种模式

### `--from-spec`（有技术方案，优先）

代码有对应技术方案 md → **从 spec 派生，不猜**：

1. 读技术方案 md（接口清单/JSON 示例/验收场景/注释要求章节）
2. 匹配代码元素到 spec 项
3. 从 spec 抄业务含义、约束条件、@throws 场景生成文档注释
4. 匹配不上 spec 的代码 → 对该部分降级为 `--from-code` 处理

### `--from-code`（无 spec，仅事实注释）

无技术方案 → 只写"有据"注释，按可信度分级：

| 注释内容 | 来源 | 策略 |
|---|---|---|
| @param | 签名 + 参数名 + 校验代码 | 直接写 |
| @return | 返回类型 + return 语句 | 直接写 |
| @throws | throw / 调用链 | 直接写 |
| 业务意图（为什么） | 调用方 + 测试断言 + 命名 | 推导得出才写；**否则不写** |

## 缺口扫描（先扫后补——防长文件漏注释的强制机制）

长文件单靠 AI 通读后凭印象补注释，**后半部分与深层嵌套代码必然被跳过**（注意力衰减）。补注释必须**先产出缺口清单，再按清单逐个补齐**，禁止直接通读全文件后凭印象开补。

### 第 1 步：产出缺口清单（文件:行号:元素名）

对目标代码**逐文件**执行「结构清单 + 注释存在性检查」：

1. **列结构清单**：用 ast-grep / LSP 符号表列出文件全部类、方法、字段声明（附行号）。Java 示例 pattern：
   - 类：`class $NAME { $$$ }`（含 interface / enum / record / 嵌套类）
   - 方法：`public $RET $NAME($$$) { $$$ }`（含 protected / private / 静态变体）
   - 字段：`private $TYPE $NAME;`（含其他修饰符变体）
2. **查注释存在性**：对清单中每个元素，检查其声明**上方是否有文档注释**（`/** ... */`）
3. **不合格判定**：无 `/**` 文档注释 / 只有单行 `//` / 方法参数 ≥2 个但 Javadoc 无 @param / 类注释未写职责 → 均记入缺口清单

产出格式（供逐个补齐与复核复用）：

```
<文件>:<行号>:<元素类型>:<元素名>:<缺口描述>
```

### 第 2 步：按清单逐个补齐

- 一个文件一个文件处理；文件内按「类 → 方法 → 字段」顺序逐个补齐，**补完一个勾掉一个**
- 每个文件完成后独立提交（commit message = 补注释: 文件路径）

### 第 3 步：重扫复核（清单清零才算完成）

- 全部补齐后**重跑第 1 步扫描指令**，对比缺口清单：应为空
- 仍有残留 → 继续补齐后重扫，直到清零
- 残留项无法判定（猜不出意图）→ 按 --from-code 可信度降级或询问，**禁止静默跳过不记账**

## 执行规则（硬性约束，不可协商）

```
1. 遵守注释规范（comment-standards.md）：全量注释 —— 所有类（DTO/VO/Config 等，仅示例非穷举）类注释、
   所有变量/字段注释、所有方法（含测试方法）注释（@param/@return 业务含义）、
   方法体 ≥2 个逻辑步骤编号步骤注释
2. 已有合格注释不覆盖，只补缺失或不合格的
3. 禁止修改业务逻辑，只增删注释
4. 猜不出的意图不写，禁止编造行为描述（业务意图无 spec 时按 --from-code 可信度分级处理）
5. 每个文件完成后独立提交（commit message = 补注释: 文件路径）
6. 先扫后补：按「缺口扫描」章节产出清单（文件:行号:元素名）后逐个补齐，禁止通读全文件凭印象补
7. 全部补齐后重跑扫描复核，缺口清单清零才算完成（残留项不静默跳过）
```

## 输出

- 补全注释的代码
- 注释核对结果（复用 comment-standards.md 自检清单核对项）

## 完成标准

- [ ] 所有类（DTO/VO/Config 等，仅示例非穷举）有类注释，写清职责
- [ ] 所有变量/字段有注释，写清业务含义
- [ ] 所有方法（含测试方法）有注释：功能 + @param + @return
- [ ] 方法体 ≥2 个逻辑步骤有编号步骤注释
- [ ] 无逐行翻译式注释、无遗漏注释项
- [ ] 注释与代码事实一致（抽查，禁止编造意图）
- [ ] 缺口清单清零（先扫后补：扫描产出清单 → 逐个补 → 重扫复核无残留）
- [ ] 未修改任何业务逻辑
- [ ] 已有合格注释未被破坏
